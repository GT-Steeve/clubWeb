🎭 Scénarios JavaScript
Scénario 1
🖥️ Tu écris <script src="script.js"></script> dans le <head> de ta page sans l'attribut defer. Ton script essaie de sélectionner un bouton avec getElementById. Que se passe-t-il ?
Le script fonctionne normalement — l'ordre n'a pas d'importance
Le script s'exécute avant que le HTML soit chargé — getElementById retourne null et le bouton n'est pas trouvé
Le navigateur attend automatiquement que le HTML soit prêt
✓ Sans defer, le script s'exécute immédiatement en lisant le fichier — le HTML n'est pas encore parsé. Place toujours <script> avant </body> ou ajoute defer dans le <head>.
Scénario 2
🖥️ Tu veux comparer si le score est égal à 100. Tu écris if (score == 100). Ton collègue te dit d'utiliser === à la place. Pourquoi ?
=== est plus rapide à exécuter
=== compare aussi le type — "100" == 100 retourne true avec ==, mais false avec ===
C'est juste une convention — les deux font exactement la même chose
✓ == convertit les types avant de comparer (coercion). "100" == 100 vaut true ce qui peut causer des bugs. === vérifie le type ET la valeur — toujours préférer ===.
Scénario 3
🖥️ Tu veux cacher un bouton HTML depuis JavaScript. Quelle est la bonne façon de faire ?
bouton.delete()
bouton.visible = false
bouton.style.display = 'none'
✓ On modifie le style CSS via JS avec element.style.display = 'none'. Pour le rendre visible à nouveau : 'block'. On peut aussi utiliser classList.add('hidden') avec une classe CSS.
