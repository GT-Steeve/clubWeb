Concepts clés du jeu Canvas
requestAnimationFrame(loop)↻
Demande au navigateur d'appeler loop à la prochaine frame — 60 fois/s. Synchronisé avec l'écran. Jamais setInterval pour un jeu.
Ordre de la boucle de jeu↻
update() → déplacer
checkCollisions() → tester
draw() → dessiner
→ requestAnimationFrame
ctx.clearRect(0,0,W,H)↻
Efface tout le canvas avant de redessiner. Sans ça, les objets laissent une traînée — le fond de la frame précédente reste visible.
Collision AABB↻
Axis-Aligned Bounding Box — test de chevauchement de deux rectangles via 4 conditions sur x, y, w, h. Méthode la plus simple pour les jeux 2D.
Pourquoi l'objet touches{} ?↻
keydown déclenche une fois par appui. Pour un déplacement continu, on mémorise true/false par touche et on consulte l'état à chaque frame dans update().
cancelAnimationFrame(animId)↻
Arrête la boucle de jeu. animId est la valeur retournée par requestAnimationFrame. Indispensable dans showGameOver() pour stopper le rendu.
ctx.beginPath() + ctx.fill()↻
Pour dessiner un cercle ou un chemin : toujours beginPath() avant arc(), puis fill() ou stroke() pour colorier. Sans beginPath, les chemins s'accumulent.
width/height sur la balise HTML↻
La résolution du canvas doit être définie dans la balise HTML, pas dans le CSS. Le CSS étire le canvas sans changer sa résolution interne → dessin flou et coordonnées fausses.
balles.filter() dans update()↻
Supprimer les balles sorties du canvas. Sans filter(), les balles continuent à exister et à être calculées hors écran — le jeu ralentit progressivement.
Math.max(0, Math.min(W-w, x))↻
Bornage du joueur dans le canvas. Empêche de sortir à gauche (min 0) et à droite (max W - largeur du joueur).

04 — Scénarios de débogage — que faites-vous ?
Scénario 1 — Écran noir
🕹️ Tu lances ton jeu pour la première fois. L'écran du canvas est complètement noir — rien ne s'affiche. La console F12 ne montre aucune erreur. Que vérifies-tu ?
Recharger la page plusieurs fois jusqu'à ce que ça apparaisse
Vérifier que draw() est bien appelée dans la boucle ET que clearRect n'efface pas après avoir dessiné — l'ordre compte
Changer la couleur du fond en blanc dans le CSS
✓ Un canvas noir sans erreur JS signifie soit que draw() n'est pas appelée (boucle non lancée ou enCours=false), soit que clearRect() est appelé après le dessin (qui efface tout). Vérifier l'ordre dans gameLoop() : update → checkCollisions → draw. Appeler draw() directement dans la console pour tester isolément.
Scénario 2 — Ralentissement progressif
🕹️ Ton jeu fonctionne parfaitement les 30 premières secondes, puis commence à ralentir de plus en plus jusqu'à se figer. Quelle est la cause la plus probable ?
Le canvas n'est pas assez grand pour contenir tous les ennemis
Les tableaux balles[] et/ou ennemis[] grossissent sans être filtrés — les objets sortis de l'écran sont encore calculés et dessinés
requestAnimationFrame est trop rapide pour ce navigateur
✓ C'est la fuite mémoire classique des jeux Canvas. Sans .filter() dans update(), les tableaux accumulent des milliers d'objets invisibles. Chaque frame les calcule tous — le CPU est saturé. Solution : toujours filtrer les objets hors canvas à la fin de chaque update().
Scénario 3 — Collision qui ne marche pas
🕹️ Les balles passent à travers les ennemis sans les détruire. Tu as bien généré checkCollisions() avec l'IA. La console ne montre aucune erreur. Que vérifies-tu ?
Que checkCollisions() est bien appelée dans gameLoop(), ET que les propriétés utilisées (x, y, w, h) correspondent exactement à la structure de tes objets balle et ennemi
Augmenter la taille des balles pour qu'elles soient plus faciles à toucher
Changer requestAnimationFrame en setInterval pour ralentir le jeu
✓ Deux causes classiques : (1) checkCollisions() n'est pas dans gameLoop() — facile à oublier lors de l'assemblage. (2) L'IA a généré la collision avec des propriétés différentes : si tes balles ont {x, y, rayon} mais que la collision attend {x, y, w, h}, les calculs échouent silencieusement. Toujours donner la structure exacte des objets dans le prompt.
Scénario 4 — Double boucle au restart
🕹️ Quand le joueur clique "Rejouer" après un Game Over, le jeu repart mais semble aller deux fois plus vite. À chaque mort, ça accélère encore. Pourquoi ?
Le score n'est pas réinitialisé à zéro
La fonction init() relance gameLoop() sans avoir arrêté l'ancienne boucle — deux boucles tournent en parallèle, puis trois, etc.
requestAnimationFrame s'emballe après un Game Over
✓ C'est l'erreur de boucle double. La solution : toujours appeler cancelAnimationFrame(animId) ET clearInterval(spawnTimer) au début de init() avant de relancer gameLoop(). Sans ça, l'ancienne boucle continue de tourner en parallèle avec la nouvelle — le rendu et les updates s'accumulent.

function update() {

  // Déplacer le joueur
  if (touches['ArrowLeft'])  joueur.x -= joueur.;
  if (touches['ArrowRight']) joueur.x += joueur.vitesse;

  // Bornage dans le canvas
  joueur.x = Math.max(0, Math.min(W - joueur.w, joueur.x));

  // Déplacer balles vers le haut + supprimer hors canvas
  balles = balles
    .map(b => ({ ...b, y: b.y - b. }))
    .(b => b.y > 0);

  // Déplacer ennemis vers le bas + supprimer hors canvas

    .map(e => ({ ...e, y: e.y + e.vitesse }))

}

function draw() {

  // Effacer le canvas
  ctx.(0, 0, W, H);

  // Fond noir
  ctx.fillStyle = '#0a0a1a';
  ctx.fillRect(0, 0, W, H);

  // Dessiner chaque balle (cercle jaune)
  balles.forEach(b => {
    ctx.();
    ctx.arc(b.x, b.y, 5, 0, Math.PI * 2);
    ctx.fillStyle = '#f1c40f';
    ctx.();
  });

  // HUD — score en haut à gauche
  ctx.fillStyle = '#fff';
  ctx.font = 'bold 18px Arial';
  ctx.textAlign = 'left';
  ctx.fillText(`Score : `, 16, 30);
}
