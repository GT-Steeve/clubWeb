Ce que le Canvas change par rapport au DOM

Un site web affiche des balises HTML que le navigateur positionne. Un jeu, lui, dessine des pixels directement sur une toile vierge — le <canvas>. L'IA est particulièrement forte pour ce type de code car les formules (physique, collision, animation) sont bien documentées et répétitives.

🏗️ HTML — Une seule balise <canvas> + les éléments de l'interface (score, boutons, écrans). Contenant
🎨 CSS — Style de la page autour du canvas (fond, centrage, police du score). Pas de CSS dans le jeu lui-même. Décor
⚡ JavaScript — Toute la logique : déplacement, collisions, score, états. Rien dans le HTML ou CSS. Moteur
🖼️ Canvas 2D API — Les méthodes de dessin : fillRect, arc, drawImage, fillText… C'est le pinceau. Rendu
💡 La règle d'or du Canvas — à chaque image (frame), on efface tout puis on redessine tout. Le jeu n'a pas de mémoire visuelle — c'est le JS qui gère l'état.
🔁
La boucle de jeu — le cœur de tout

La boucle de jeu tourne en permanence, aussi vite que le navigateur peut — en général 60 fois par seconde. C'est le rythme cardiaque du jeu. Chaque battement = 1 frame.

🧠 requestAnimationFrame(loop) est la clé. Il demande au navigateur d'appeler la fonction loop lors de la prochaine frame disponible, synchronisé avec le taux de rafraîchissement de l'écran. Jamais de setInterval pour un jeu.
01 — Initialiser le Canvas
🖼️index.htmlMettre en place la scène

Le HTML d'un jeu Canvas est minimaliste : une balise <canvas>, un lien CSS, un lien JS. Tout le reste se passe en JavaScript.

index.html 
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <link rel="stylesheet" href="style.css">
  <title>Mon Jeu</title>
</head>
<body>
  <!-- L'écran du jeu — width/height en px OBLIGATOIRE ici -->
  <canvas id="gameCanvas" width="800" height="500"></canvas>

  <!-- Score et interface -->
  <div id="ui">
    Score : <span id="score">0</span>
  </div>

  <!-- JS en bas du body -->
  <script src="game.js"></script>
</body>
</html>
game.js — Initialisation du Canvas 
// Récupérer le canvas et son contexte de dessin 2D
const canvas = document.getElementById('gameCanvas');
const ctx    = canvas.getContext('2d');  // ctx = le pinceau

// Dimensions accessibles partout dans le code
const W = canvas.width;   // 800
const H = canvas.height;  // 500
🚨 width/height dans le HTML, pas dans le CSS — Si tu mets width: 800px dans le CSS sans le mettre dans la balise HTML, le canvas sera étiré mais sa résolution interne restera 300×150 (valeur par défaut). Les coordonnées seront toutes fausses.

02 — Architecture d'un jeu en fonctions
🏗️
Découper le jeu en fonctions — la clé de l'assemblage IA

Un jeu bien structuré est une suite de fonctions indépendantes qui jouent chacune un rôle précis. C'est cette architecture qui permet de demander à l'IA une fonction à la fois, puis de les assembler.

📋 game.js — Architecture complète d'un shooter
init()
Initialise l'état du jeu : position du joueur, tableau des ennemis vide, score à 0
gameLoop()
La boucle principale — appelle update(), checkCollisions(), draw() puis se rappelle elle-même via requestAnimationFrame
update()
Déplace tous les objets : joueur selon les touches, balles vers le haut, ennemis vers le bas
checkCollisions()
Teste si deux objets se chevauchent — supprime balle + ennemi en cas de contact, décrémente vie si ennemi touche le joueur
draw()
Efface le canvas, puis redessine le fond, les ennemis, les balles, le joueur, le score
spawnEnemy()
Crée un ennemi à une position X aléatoire en haut du canvas et l'ajoute au tableau ennemis[]
shoot()
Crée une balle à la position du joueur et l'ajoute au tableau balles[]
showGameOver()
Arrête la boucle, affiche l'écran Game Over avec le score final et un bouton Rejouer
🧩 Demande une fonction à la fois à l'IA. « Génère la fonction checkCollisions() qui teste si un rectangle et un cercle se chevauchent » donne un résultat bien plus précis que « génère tout le jeu ».
03 — L'état du jeu — les variables partagées
📦Variables globalesLa mémoire du jeu

Les objets et tableaux qui décrivent l'état du jeu sont déclarés en haut du fichier, accessibles par toutes les fonctions. C'est ce que l'IA doit connaître avant de générer chaque fonction.

game.js — Variables d'état 
// ── JOUEUR ─────────────────────────────────────
const joueur = {
  x: 380,        // position horizontale
  y: 450,        // position verticale (en bas)
  w: 40,         // largeur
  h: 30,         // hauteur
  vitesse: 5,   // pixels par frame
  vies: 3
};

// ── TABLEAUX (listes d'objets dynamiques) ──────
let balles  = [];  // { x, y, vitesse }
let ennemis = [];  // { x, y, w, h, vitesse }

// ── SCORE ET ÉTAT ──────────────────────────────
let score     = 0;
let enCours   = false;  // true = jeu actif
let animId    = null;   // id retourné par requestAnimationFrame

// ── TOUCHES PRESSÉES ────────────────────────────
const touches = {};
document.addEventListener('keydown', e => touches[e.key] = true);
document.addEventListener('keyup',   e => touches[e.key] = false);
Pourquoi l'objet touches{} ?
keydown déclenche un événement quand une touche est appuyée. Mais si le joueur maintient la flèche gauche, le déplacement doit être continu à chaque frame. L'objet touches agit comme un registre permanent : vrai si la touche est enfoncée, faux dès qu'elle est relâchée. La fonction update() le consulte à chaque frame.
04 — Les fonctions clés — générées par l'IA
🔄update()Déplacer les objets
Prompt pour générer update()
> Génère la fonction update() d'un jeu Canvas shooter. Variables disponibles : joueur {x,y,w,h,vitesse}, balles[], ennemis[], touches{}, W=800, H=500. La fonction doit : 1. Déplacer le joueur gauche/droite avec ArrowLeft/ArrowRight en le bloquant dans les bords du canvas 2. Déplacer chaque balle vers le haut (y diminue) 3. Supprimer les balles sorties du canvas (y < 0) 4. Déplacer chaque ennemi vers le bas (y augmente) 5. Supprimer les ennemis sortis en bas
update() — généré par l'IA 
function update() {

  // 1. Déplacement joueur
  if (touches['ArrowLeft'])  joueur.x -= joueur.vitesse;
  if (touches['ArrowRight']) joueur.x += joueur.vitesse;
  // Bloquer dans les bords
  joueur.x = Math.max(0, Math.min(W - joueur.w, joueur.x));

  // 2 & 3. Balles : déplacer vers le haut + filtrer hors canvas
  balles = balles
    .map(b => ({ ...b, y: b.y - b.vitesse }))
    .filter(b => b.y > 0);

  // 4 & 5. Ennemis : déplacer vers le bas + filtrer hors canvas
  ennemis = ennemis
    .map(e => ({ ...e, y: e.y + e.vitesse }))
    .filter(e => e.y < H + 50);
}
🧠 .map().filter() — map crée un nouveau tableau avec les objets déplacés. filter garde uniquement ceux qui vérifient la condition. Enchaîner les deux en une ligne évite les boucles for complexes avec des suppressions d'index.
💥checkCollisions()Détecter les impacts
Prompt pour checkCollisions()
> Génère la fonction checkCollisions() pour un shooter Canvas. Chaque balle : { x, y, r:5 } (cercle, rayon 5) Chaque ennemi : { x, y, w:40, h:30 } (rectangle) Joueur : { x, y, w:40, h:30 } (rectangle) Tester : - balle touche ennemi → supprimer les deux, score += 10 - ennemi touche joueur → supprimer ennemi, joueur.vies-- si vies == 0 → appeler showGameOver() Utilise une détection AABB (rectangle vs rectangle) pour simplifier — la balle peut être traitée comme un carré 10x10.
checkCollisions() — généré par l'IA 
// Test de chevauchement rectangle vs rectangle (AABB)
function rectsSeChevanchent(a, b) {
  return a.x < b.x + b.w &&
         a.x + a.w > b.x &&
         a.y < b.y + b.h &&
         a.y + a.h > b.y;
}

function checkCollisions() {

  // Balle vs Ennemi
  balles = balles.filter(balle => {
    let toucheEnnemi = false;

    ennemis = ennemis.filter(ennemi => {
      const ballRect = { x: balle.x - 5, y: balle.y - 5, w: 10, h: 10 };
      if (rectsSeChevanchent(ballRect, ennemi)) {
        score += 10;
        toucheEnnemi = true;
        return false; // supprime l'ennemi
      }
      return true;
    });

    return !toucheEnnemi; // supprime la balle si elle a touché
  });

  // Ennemi vs Joueur
  ennemis = ennemis.filter(ennemi => {
    if (rectsSeChevanchent(joueur, ennemi)) {
      joueur.vies--;
      if (joueur.vies <= 0) showGameOver();
      return false; // supprime l'ennemi qui touche
    }
    return true;
  });
}
🖼️draw()Dessiner chaque frame
Prompt pour draw()
> Génère la fonction draw() pour notre shooter Canvas. Ordre de dessin (du fond vers l'avant) : 1. Effacer tout le canvas 2. Fond noir / fond étoilé (simple) 3. Ennemis : rectangles rouges avec un texte 👾 centré 4. Balles : petits cercles jaunes 5. Joueur : triangle vert pointé vers le haut 6. HUD : score en haut à gauche, vies en haut à droite
draw() — généré par l'IA 
function draw() {
  // 1. Effacer
  ctx.clearRect(0, 0, W, H);

  // 2. Fond
  ctx.fillStyle = '#0a0a1a';
  ctx.fillRect(0, 0, W, H);

  // 3. Ennemis
  ennemis.forEach(e => {
    ctx.fillStyle = '#e74c3c';
    ctx.fillRect(e.x, e.y, e.w, e.h);
    ctx.fillStyle = '#fff';
    ctx.font = '20px serif';
    ctx.textAlign = 'center';
    ctx.fillText('👾', e.x + e.w/2, e.y + e.h/2 + 7);
  });

  // 4. Balles
  balles.forEach(b => {
    ctx.beginPath();
    ctx.arc(b.x, b.y, 5, 0, Math.PI * 2);
    ctx.fillStyle = '#f1c40f';
    ctx.fill();
  });

  // 5. Joueur (triangle)
  ctx.beginPath();
  ctx.moveTo(joueur.x + joueur.w/2, joueur.y);          // pointe
  ctx.lineTo(joueur.x,           joueur.y + joueur.h);  // bas gauche
  ctx.lineTo(joueur.x + joueur.w, joueur.y + joueur.h); // bas droite
  ctx.closePath();
  ctx.fillStyle = '#2ecc71';
  ctx.fill();

  // 6. HUD
  ctx.fillStyle = '#fff';
  ctx.font = 'bold 18px Arial';
  ctx.textAlign = 'left';
  ctx.fillText(`Score : ${score}`, 16, 30);
  ctx.textAlign = 'right';
  ctx.fillText(`Vies : ${'❤️'.repeat(joueur.vies)}`, W - 16, 30);
}
🎨 L'ordre de dessin = les couches visuelles — Ce qui est dessiné en premier est "derrière". Fond → ennemis → balles → joueur → HUD. Si tu dessines le fond en dernier, il efface tout.
05 — Assembler la boucle de jeu
🔗gameLoop() + init() + spawnTout assembler

Une fois toutes les fonctions générées séparément, on les assemble dans la boucle principale. C'est la fonction qui relie tout.

game.js — Boucle + Init + Spawn 
// ── BOUCLE PRINCIPALE ──────────────────────────
function gameLoop() {
  if (!enCours) return;  // stopper si jeu terminé

  update();             // 1. Déplacer
  checkCollisions();    // 2. Tester les impacts
  draw();               // 3. Dessiner

  animId = requestAnimationFrame(gameLoop);  // 4. Rappeler
}

// ── INITIALISATION ─────────────────────────────
function init() {
  joueur.x = W / 2 - joueur.w / 2;
  joueur.vies = 3;
  balles  = [];
  ennemis = [];
  score   = 0;
  enCours = true;

  // Spawn d'ennemis toutes les 1.5 secondes
  clearInterval(spawnTimer);
  spawnTimer = setInterval(spawnEnemy, 1500);

  gameLoop();  // démarrer la boucle
}

// ── SPAWN D'ENNEMIS ────────────────────────────
let spawnTimer;
function spawnEnemy() {
  if (!enCours) return;
  ennemis.push({
    x: Math.random() * (W - 40),  // position X aléatoire
    y: -40,                          // hors écran en haut
    w: 40, h: 30,
    vitesse: 2 + Math.random() * 2  // vitesse aléatoire
  });
}

// ── TIRER ──────────────────────────────────────
document.addEventListener('keydown', e => {
  if (e.key === ' ' && enCours) {  // Espace = tirer
    balles.push({
      x: joueur.x + joueur.w / 2,
      y: joueur.y,
      vitesse: 8
    });
  }
});

// ── GAME OVER ──────────────────────────────────
function showGameOver() {
  enCours = false;
  cancelAnimationFrame(animId);
  clearInterval(spawnTimer);

  ctx.fillStyle = 'rgba(0,0,0,0.75)';
  ctx.fillRect(0, 0, W, H);
  ctx.fillStyle = '#fff';
  ctx.font = 'bold 48px Arial';
  ctx.textAlign = 'center';
  ctx.fillText('GAME OVER', W/2, H/2 - 20);
  ctx.font = '24px Arial';
  ctx.fillText(`Score final : ${score}`, W/2, H/2 + 30);
}

// ── LANCER LE JEU ──────────────────────────────
init();
06 — Méthode d'assemblage avec l'IA
🔗
Comment imbriquer des fonctions qui se parlent

Le danger du vibecoding jeu est que l'IA génère des fonctions avec des noms de variables différents à chaque fois. Voici la méthode pour que tout se tienne.

Déclarer d'abord toutes les variables globalesAvant de demander la moindre fonction, définir et coller à l'IA : noms et structure de joueur, balles[], ennemis[], touches{}, W, H. Ce sont les contrats que toutes les fonctions respecteront.
Toujours inclure le contexte dans chaque promptChaque prompt doit commencer par : « Voici mes variables disponibles : [coller les variables]. Génère la fonction X qui… ». L'IA ne peut pas deviner les noms que tu as choisis.
Tester chaque fonction isolémentAprès avoir intégré draw(), appeler draw() une fois directement dans la console F12 pour vérifier le rendu avant de connecter la boucle. Si ça plante, c'est dans draw(), pas ailleurs.
Vérifier les références croiséesSi checkCollisions() appelle showGameOver(), cette fonction doit exister avant dans le fichier — ou au minimum être déclarée avec function (hoisting). Les fonctions fléchées const fn = () => {} ne bénéficient pas du hoisting.
Lire la console après chaque ajoutF12 → Console. Une erreur dans update() empêche draw() de s'exécuter — la page est noire. Identifier la ligne, coller le message à l'IA avec le contexte.

Règles d'or du vibecoding jeu Canvas
Une fonction à la foisNe jamais demander « génère tout le jeu ». Chaque fonction a un rôle unique — les demander séparément donne un code lisible et assemblable.
Toujours donner les variables à l'IAColler les déclarations globales dans chaque prompt. L'IA ne connaît pas ton code précédent — elle recommence à chaque fois.
Tester dans le navigateur après chaque fonctionAjouter update() → F5 → tester. Ajouter checkCollisions() → F5 → tester. Ne jamais tout ajouter d'un coup.
F12 est ton meilleur amiLa console dit exactement quelle ligne a planté. Avant de coller une erreur à l'IA, la lire — 70% du temps la solution est évidente.
Commenter les liaisons entre fonctionsAu-dessus de chaque appel dans gameLoop(), un commentaire court : ce que la fonction fait, ce qu'elle lit, ce qu'elle modifie. Ça te sauvera lors du débogage.
