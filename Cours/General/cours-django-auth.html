Le concept — deux types d'utilisateurs
👥
Visiteur vs Créateur

Presque tous les sites web distinguent deux types de personnes. Imaginez un blog : tout le monde peut lire les articles, mais seul l'auteur peut en écrire ou en supprimer.

👁️ Visiteur (non connecté) Lit les articles
Voit les pages publiques
Ne peut rien créer
✍️ Créateur (connecté) Écrit des articles
Modifie son contenu
Accède au tableau de bord

Django gère tout ça nativement, sans installer quoi que ce soit. Le système d'auth est déjà là — il suffit de l'activer et de s'en servir.

🎯 Bonne nouvelle ! Django inclut un système complet d'utilisateurs, de mots de passe chiffrés, de sessions et de permissions. On ne le réinvente pas — on l'utilise.
01 — Brancher les URLs d'authentification
🗺️ monsite/urls.py Une seule ligne suffit

Django fournit des vues prêtes à l'emploi pour la connexion, la déconnexion et la gestion du mot de passe. On les branche en une ligne dans le routeur principal.

monsite/urls.py 
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('blog/', include('blog.urls')),

    # ↓ Toutes les vues auth Django en une ligne
    path('accounts/', include('django.contrib.auth.urls')),

    # ↓ Notre vue d'inscription (à créer)
    path('accounts/inscription/', views_auth.inscription, name='inscription'),
]
URLs disponibles automatiquement après include
/accounts/login/ → page de connexion
/accounts/logout/ → déconnexion
/accounts/password_change/ → changer son mot de passe
/accounts/inscription/ → notre page d'inscription (à créer)
⚠️ L'inscription n'est pas incluse par défaut — Django gère connexion et déconnexion, mais pas la création de compte. On doit écrire cette vue nous-mêmes.
02 — Le template de connexion
🎨 templates/registration/login.html Page de connexion attendue par Django

Django cherche le template de connexion dans un chemin précis : templates/registration/login.html. Ce dossier registration/ est une convention Django — respectez-le.

templates/registration/login.html 
{% extends "base.html" %}
{% block content %}

<h2>Connexion</h2>

<form method="post">
    {% csrf_token %}      <!-- protection sécurité obligatoire -->
    {{ form.as_p }}          <!-- Django génère les champs automatiquement -->
    <button type="submit">Se connecter</button>
</form>

<p>Pas encore de compte ?
    <a href="{% url 'inscription' %}">S'inscrire</a>
</p>

{% endblock %}
🔒 {% csrf_token %} est obligatoire sur chaque formulaire POST. C'est une protection contre les attaques CSRF. Django refusera le formulaire si ce tag est absent.

Où rediriger après connexion ?

Par défaut Django redirige vers /accounts/profile/. On change ça dans settings.py :

monsite/settings.py 
# Après connexion → accueil du blog
LOGIN_REDIRECT_URL = '/'

# Après déconnexion → page de connexion
LOGOUT_REDIRECT_URL = '/accounts/login/'

# Si accès interdit → rediriger vers connexion
LOGIN_URL = '/accounts/login/'
03 — Créer la vue d'inscription
📝 blog/views.py Vue d'inscription avec UserCreationForm

Django fournit un formulaire prêt à l'emploi : UserCreationForm. Il gère la vérification des mots de passe, les validations, tout. On l'utilise dans notre vue.

blog/views.py 
from django.contrib.auth.forms import UserCreationForm
from django.contrib.auth import login
from django.shortcuts import render, redirect

def inscription(request):
    if request.method == 'POST':
        form = UserCreationForm(request.POST)
        if form.is_valid():
            user = form.save()          # crée l'utilisateur en BDD
            login(request, user)         # le connecte immédiatement
            return redirect('blog:liste') # redirige vers le blog
    else:
        form = UserCreationForm()

    return render(request, 'registration/inscription.html', {'form': form})
Ce que fait cette vue
1. Si requête GET → affiche le formulaire vide
2. Si requête POST → valide les données
3. Si valide → crée l'utilisateur + le connecte + redirige
4. Si invalide → réaffiche le formulaire avec les erreurs

Le template d'inscription

templates/registration/inscription.html 
{% extends "base.html" %}
{% block content %}

<h2>Créer un compte</h2>

<form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Créer mon compte</button>
</form>

<p>Déjà un compte ?
    <a href="{% url 'login' %}">Se connecter</a>
</p>

{% endblock %}
04 — Protéger les vues avec @login_required
🛡️ blog/views.py Filtrer visiteur et créateur

Le décorateur @login_required est la clé. Placez-le au-dessus d'une vue — si l'utilisateur n'est pas connecté, Django le redirige automatiquement vers la page de connexion.

blog/views.py 
from django.contrib.auth.decorators import login_required

# ✅ ACCESSIBLE À TOUS — visiteurs inclus
def liste_articles(request):
    articles = Article.objects.filter(publie=True)
    return render(request, 'blog/article_list.html', {'articles': articles})

# 🔐 RÉSERVÉ AUX CONNECTÉS — @login_required bloque les visiteurs
@login_required
def creer_article(request):
    # seuls les utilisateurs connectés arrivent ici
    return render(request, 'blog/creer_article.html')

@login_required
def tableau_de_bord(request):
    # articles créés par l'utilisateur connecté uniquement
    mes_articles = Article.objects.filter(auteur=request.user)
    return render(request, 'blog/dashboard.html', {'articles': mes_articles})
🪄 request.user — Dans toutes les vues, Django met automatiquement l'utilisateur connecté dans request.user. Si personne n'est connecté, c'est un objet AnonymousUser.

Savoir si l'utilisateur est connecté dans un template

templates/base.html 
{% if user.is_authenticated %}
    <!-- Affiché uniquement si connecté -->
    <p>Bonjour {{ user.username }} !</p>
    <a href="{% url 'tableau_de_bord' %}">Mon tableau de bord</a>
    <a href="{% url 'logout' %}">Se déconnecter</a>
{% else %}
    <!-- Affiché si visiteur non connecté -->
    <a href="{% url 'login' %}">Se connecter</a>
    <a href="{% url 'inscription' %}">S'inscrire</a>
{% endif %}
🍝 Effet spaghetti classique — Cacher un bouton "Créer un article" dans le template ne suffit pas à protéger la vue ! Un visiteur peut taper directement l'URL. Il faut toujours @login_required sur la vue, en plus du masquage visuel dans le template.
05 — Relier un article à son auteur
🔗 blog/models.py ForeignKey vers l'utilisateur Django

Pour savoir "qui a écrit quoi", on relie le model Article au model User de Django avec une ForeignKey.

blog/models.py 
from django.db import models
from django.contrib.auth.models import User

class Article(models.Model):
    titre    = models.CharField(max_length=200)
    contenu  = models.TextField()
    publie   = models.BooleanField(default=False)

    # Lien vers l'utilisateur Django — clé étrangère
    auteur   = models.ForeignKey(
        User,
        on_delete=models.CASCADE,   # supprime les articles si l'user est supprimé
        related_name='articles'     # user.articles.all() donnera ses articles
    )

    def __str__(self):
        return f"{self.titre} — par {self.auteur.username}"

Sauvegarder l'auteur automatiquement à la création

blog/views.py 
@login_required
def creer_article(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            article = form.save(commit=False) # ne sauvegarde pas encore
            article.auteur = request.user       # on ajoute l'auteur
            article.save()                    # maintenant on sauvegarde
            return redirect('blog:liste')
    else:
        form = ArticleForm()
    return render(request, 'blog/creer_article.html', {'form': form})
💡 save(commit=False) — Ce paramètre crée l'objet Python sans l'écrire en base de données. On peut ainsi modifier des champs (ici auteur) avant la vraie sauvegarde.
