Pas d'idée ? Pong, Breakout, Space Invaders, Snake, Pac-Man, Asteroids — tous se construisent avec la même méthode.
Progression 0 / 6 étapes
1
Analyser ton jeu — avant d'écrire une ligne
▼

La première étape ne touche pas le clavier : observe ton jeu pendant 5 minutes. Note tout ce que tu vois. Ensuite, identifie la mécanique centrale — le truc sans lequel le jeu n'existe pas.

Questions à te poser
Qu'est-ce qui bouge ?Le joueur ? Les ennemis ? Le décor ?
Quelle est la physique ?Gravité, vitesse constante, rebond ?
Comment perd-on ?Collision ? Temps écoulé ? Chute ?
Comment gagne-t-on du score ?Temps survécu, ennemis éliminés, pièces ?
Exemple — Dino Run analysé
// Mécanique centrale : saut par-dessus des obstacles défilants // // Entités : // • dino — joueur fixe en x, soumis à la gravité, peut sauter // • cactus — obstacles qui défilent de droite à gauche // • sol — ligne fixe, dino rebondit dessus // // Perd si : dino touche un cactus // Score : temps survécu (frames / 60 = secondes) // Difficulté : vitesse augmente toutes les 5 secondes
📋
Écris cette analyse dans un commentaire en haut de ton script.js. Ça te servira de boussole quand tu seras bloqué : "est-ce que ce que j'ajoute est dans l'analyse ?"
2
Le personnage & la physique
▼

Commence par faire bouger le personnage seul, sans obstacle ni score. La physique doit être satisfaisante avant de passer à la suite — c'est la fondation de tout.

Structure de base — à adapter selon ton jeu
const GRAVITE = 0.5; // accélération vers le bas const FORCE_SAUT = -11; // vitesse initiale vers le haut const SOL = 220; // y du sol (adapter à la hauteur du canvas) let joueur = { x: 80, y: SOL - 50, // position vx: 0, vy: 0, // vitesse w: 40, h: 50, // taille de la hitbox sol: false // est-il au sol ? }; function update() { // 1. Appliquer la gravité joueur.vy += GRAVITE; joueur.y += joueur.vy; // 2. Empêcher de passer sous le sol if (joueur.y >= SOL - joueur.h) { joueur.y = SOL - joueur.h; joueur.vy = 0; joueur.sol = true; } } function sauter() { if (joueur.sol) { // saut simple joueur.vy = FORCE_SAUT; joueur.sol = false; } } document.addEventListener('keydown', function(e) { if (e.code === 'Space' || e.code === 'ArrowUp') sauter(); });
🎮
Pour un jeu sans gravité (Snake, Pong), remplace la gravité par une vitesse constante : joueur.x += joueur.vx; joueur.y += joueur.vy;. Le principe reste le même — position + vitesse chaque frame.
3
Les obstacles défilants
▼

Les obstacles naissent hors de l'écran à droite, se déplacent vers la gauche, et sont supprimés quand ils sortent à gauche. Un compteur de frames contrôle l'intervalle entre les apparitions.

Génération & défilement
const BASE_SPEED = 3; // pixels par frame const INTERVALLE = 90; // frames entre deux obstacles let obstacles = []; let vitesse = BASE_SPEED; let frameCount = 0; function spawnObstacle() { const h = 30 + Math.random() * 40; // hauteur aléatoire 30–70 obstacles.push({ x: canvas.width, w: 24, h: h, y: SOL - h }); } function updateObstacles() { frameCount++; if (frameCount % INTERVALLE === 0) spawnObstacle(); // Déplacer chaque obstacle vers la gauche obstacles.forEach(function(o) { o.x -= vitesse; }); // Supprimer ceux qui sont sortis de l'écran obstacles = obstacles.filter(function(o) { return o.x + o.w > 0; }); }
💡
filter() crée un nouveau tableau avec seulement les éléments qui passent le test. C'est plus propre qu'une boucle avec splice() — et ça évite les bugs d'index décalé lors de suppressions dans un forEach.
🔀
Pour un jeu où c'est le joueur qui se déplace (comme un platformer), c'est l'inverse : le joueur bouge, et la caméra suit. Simuler ça : déplacer toutes les entités à l'opposé de la direction du joueur.
4
La détection de collision
▼

On compare les rectangles du joueur et des obstacles. Pour un meilleur ressenti, on réduit légèrement la hitbox — le joueur frôle les obstacles sans mourir injustement.

Collision AABB avec boîte réduite
function checkCollisions() { const marge = 8; // pixels retirés sur chaque côté for (let i = 0; i < obstacles.length; i++) { const o = obstacles[i]; // Hitbox réduite du joueur const jx = joueur.x + marge; const jy = joueur.y + marge; const jw = joueur.w - marge * 2; const jh = joueur.h - marge * 2; // Test AABB : les deux rectangles se chevauchent-ils ? const collision = jx + jw > o.x && // droite J > gauche O jx < o.x + o.w && // gauche J < droite O jy + jh > o.y && // bas J > haut O jy < o.y + o.h; // haut J < bas O if (collision) { gameState = GS.OVER; // → game over break; } } }
⚠️
Les 4 conditions doivent toutes être vraies en même temps. Si tu en oublies une (par ex. la vérification de l'axe Y), des collisions fantômes apparaissent — le joueur meurt sans raison visible.
5
Score, difficulté progressive & meilleur score
▼

Le score augmente chaque frame. La vitesse augmente par paliers. Le meilleur score est sauvegardé dans localStorage pour persister entre les parties.

Score + difficulté progressive
let score = 0; let best = parseInt(localStorage.getItem('monClone_best') || '0'); function updateScore() { score++; // Augmenter la vitesse toutes les 300 frames (~5 s à 60 fps) if (score % 300 === 0) vitesse += 0.3; } function gameOver() { // Sauvegarder le meilleur score si battu if (score > best) { best = score; localStorage.setItem('monClone_best', best); } gameState = GS.OVER; } function drawHUD() { ctx.fillStyle = '#fff'; ctx.font = '700 14px Nunito'; ctx.textAlign = 'left'; ctx.fillText('Score : ' + Math.floor(score / 60), 16, 28); ctx.textAlign = 'right'; ctx.fillText('Meilleur : ' + Math.floor(best / 60), canvas.width - 16, 28); }
💾
Remplace 'monClone_best' par un nom unique à ton jeu. Si plusieurs jeux utilisent la même clé, ils partagent le meilleur score — ce qui n'est pas ce qu'on veut.
6
Machine à états & ta variante
▼

Une machine à états simplifie la gestion des écrans : titre, jeu, game over. C'est le dernier vernis une fois la mécanique centrale validée. Ensuite : ajoute une seule variante originale.

Machine à états minimale
const GS = { TITRE: 0, JEU: 1, OVER: 2 }; let gameState = GS.TITRE; function loop() { ctx.clearRect(0, 0, canvas.width, canvas.height); switch (gameState) { case GS.TITRE: drawTitre(); break; case GS.JEU: updateJeu(); drawJeu(); drawHUD(); break; case GS.OVER: drawOver(); break; } requestAnimationFrame(loop); } loop();
Idées de variantes — choisis-en une
Double sautAutoriser un deuxième saut en l'air avec un compteur sauts
Mode nuitLa couleur de fond change à partir de 30 s, les obstacles aussi
Power-upUn item qui apparaît aléatoirement et donne l'invincibilité 3 s
Obstacles volantsUn 2e type d'obstacle qui vole à mi-hauteur et nécessite de s'accroupir
🚀
Une seule variante bien finie vaut mieux que trois à moitié. Choisis celle qui te motive le plus, implémente-la, teste-la, puis décide si tu veux en ajouter une deuxième.
Pour aller plus loin
Ton clone fonctionne et ta variante est en place ? Voici quelques idées supplémentaires pour approfondir.
🎵
Sons & vibrations
Utilise l'AudioContext pour générer des bips synthétiques au saut, à la collision et au score palier. Pas besoin de fichier audio — tu crées les sons directement en JavaScript avec des oscillateurs.
📱
Contrôles tactiles
Ajoute un listener touchstart pour que le jeu fonctionne sur smartphone. Pense aussi à redimensionner le canvas en fonction de la largeur de l'écran avec window.innerWidth.
🏆
Tableau des 5 meilleurs scores
Au lieu de sauvegarder un seul best score, stocke un tableau de 5 scores avec un nom et une date. Affiche-le sur un écran dédié entre les parties — comme dans les vrais jeux d'arcade.
🎯
Clone un deuxième jeu
Une fois que la méthode est acquise, le prochain clone va beaucoup plus vite. Essaie un jeu aux mécaniques différentes : Pong (deux joueurs), Asteroids (rotation + inertie), ou Snake (grille + queue).
