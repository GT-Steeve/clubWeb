Django — "batteries included"

Django est un framework web Python haute productivité. Sa philosophie : "Ne te répète pas" (DRY — Don't Repeat Yourself) et "batteries included" — tout ce dont tu as besoin est déjà là.

Créé en 2005 dans la rédaction d'un journal en ligne (Lawrence Journal-World), Django a été conçu pour aller vite. Instagram, Pinterest et Disqus ont démarré avec Django — il passe à l'échelle mondiale.

Ce que Django fournit sans rien installer de plus
🔐 Authentification — login, logout, reset de mot de passe, gestion des rôles
🛠️ Interface admin auto-générée — CRUD sur toutes tes données en 2 lignes de code
🗄️ ORM puissant — requêtes BDD sans SQL brut
🔄 Migrations — gestion des changements de schéma BDD automatisée
🛡️ Sécurité par défaut — CSRF, XSS, injection SQL, clickjacking
📋 Système de formulaires — validation et rendu HTML intégrés
🌍 Internationalisation — traduction multilingue intégrée
🏗️ L'architecture MTV
2
MTV — Model, Template, View

Django utilise le pattern MTV — l'équivalent du MVC classique. Chaque partie a un rôle précis et bien séparé.

M
Model
Structure des données. Définit les tables BDD via des classes Python.
T
Template
L'interface utilisateur. HTML avec variables Python injectées.
V
View
La logique. Reçoit la requête, interroge le Model, retourne un Template.

📦 Les Models — définir les données
4
models.py — Les données de l'application

Un Model est une classe Python qui représente une table en base de données. Chaque attribut est un champ de la table. Django crée automatiquement le SQL correspondant.

# blog/models.py from django.db import models from django.contrib.auth.models import User class Categorie(models.Model): nom = models.CharField(max_length=100) slug = models.SlugField(unique=True) def __str__(self): return self.nom class Article(models.Model): titre = models.CharField(max_length=200) contenu = models.TextField() publie_le = models.DateTimeField(auto_now_add=True) modifie_le= models.DateTimeField(auto_now=True) actif = models.BooleanField(default=True) auteur = models.ForeignKey(User, on_delete=models.CASCADE) categorie = models.ForeignKey(Categorie, on_delete=models.SET_NULL, null=True) class Meta: ordering = ['-publie_le'] # tri par défaut : plus récent en premier def __str__(self): return self.titre # Appliquer les changements à la BDD # python manage.py makemigrations # python manage.py migrate
Types de champs Django courants
CharField — texte court (max_length requis)
TextField — texte long (article, description)
IntegerField / FloatField — nombres
BooleanField — vrai/faux
DateTimeField — date et heure
ForeignKey — relation 1:N vers une autre table
ManyToManyField — relation N:M
ImageField / FileField — upload de fichiers
5
Les migrations — synchroniser la BDD

Les migrations sont des fichiers Python générés automatiquement qui décrivent l'évolution de ta base de données. Chaque modification de Model se traduit en migration.

# 1. Générer les migrations (après modification des models) python manage.py makemigrations # 2. Appliquer les migrations à la BDD python manage.py migrate # 3. Voir les migrations en attente python manage.py showmigrations # 4. Revenir en arrière (annuler une migration) python manage.py migrate blog 0001 # revenir à la migration 0001
💡 La règle d'or : toujours versionner les migrations avec Git. Elles représentent l'historique complet de l'évolution de ta base de données.
⚙️ Les Views — la logique métier
6
views.py — Fonctions et Class-Based Views

Une View est une fonction (ou classe) Python qui reçoit une requête HTTP et retourne une réponse HTTP. C'est elle qui fait le lien entre le Model et le Template.

# blog/views.py from django.shortcuts import render, get_object_or_404 from .models import Article # View basée sur une fonction (Function-Based View) def liste_articles(request): articles = Article.objects.filter(actif=True) return render(request, 'blog/liste.html', { 'articles': articles }) def detail_article(request, pk): # get_object_or_404 → retourne 404 si l'article n'existe pas article = get_object_or_404(Article, pk=pk, actif=True) return render(request, 'blog/detail.html', {'article': article}) # View basée sur une classe (Class-Based View) — plus concise from django.views.generic import ListView, DetailView class ArticleListView(ListView): model = Article template_name = 'blog/liste.html' context_object_name = 'articles' def get_queryset(self): return Article.objects.filter(actif=True)
7
urls.py — Définir les routes

Le fichier urls.py mappe les URLs aux Views. Chaque URL correspond à une View qui traite la requête.

# monsite/urls.py (principal) from django.contrib import admin from django.urls import path, include urlpatterns = [ path('admin/', admin.site.urls), path('blog/', include('blog.urls')), # inclure les URLs de l'app blog ] # blog/urls.py (de l'application) from django.urls import path from . import views urlpatterns = [ # /blog/ → liste des articles path('', views.liste_articles, name='liste'), # /blog/42/ → détail de l'article id=42 path('<int:pk>/', views.detail_article, name='detail'), # /blog/mon-titre/ → détail par slug path('<slug:slug>/', views.detail_par_slug, name='detail-slug'), ]
🖼️ Les Templates — l'interface utilisateur
8
Le système de templates Django

Les templates sont des fichiers HTML avec des balises spéciales Django pour injecter des données et ajouter de la logique (boucles, conditions, héritage).

{# templates/base.html — le gabarit parent #} <!DOCTYPE html> <html> <head> <title>{% block titre %}Mon Site{% endblock %}</title> </head> <body> <nav>Menu commun à toutes les pages</nav> {% block contenu %} {# chaque page remplace ce bloc #} {% endblock %} </body> </html> {# templates/blog/liste.html — hérite de base.html #} {% extends "base.html" %} {% block titre %}Articles du blog{% endblock %} {% block contenu %} {% for article in articles %} <article> <h2>{{ article.titre }}</h2> <p>{{ article.contenu|truncatewords:50 }}</p> <a href="{% url 'detail' article.pk %}">Lire la suite</a> </article> {% empty %} <p>Aucun article disponible.</p> {% endfor %} {% endblock %}
Syntaxe templates Django essentielle
{{ variable }} — affiche la valeur d'une variable
{% tag %} — balise de logique (for, if, block, extends…)
{{ variable|filtre }} — transforme une variable (|truncatewords:50, |date:"d/m/Y"…)
{% url 'nom-route' %} — génère une URL depuis son nom
{% extends %} — hérite d'un template parent
{% block %} — zone remplaçable dans un template enfant
🗄️ L'ORM Django en détail
9
QuerySets — interroger la base de données

L'ORM Django produit des QuerySets — des listes de résultats paresseuses (lazy) qui ne font la requête SQL qu'au moment où on en a besoin.

# Récupérer des données Article.objects.all() # tous les articles Article.objects.filter(actif=True) # filtrés Article.objects.get(pk=1) # un seul (erreur si pas trouvé) Article.objects.exclude(actif=False) # exclure des résultats Article.objects.order_by('-publie_le') # tri décroissant Article.objects.filter(actif=True)[:10] # les 10 premiers # Lookups avancés (filtrages précis) Article.objects.filter(titre__contains="Django") # titre contient "Django" Article.objects.filter(publie_le__year=2024) # publiés en 2024 Article.objects.filter(auteur__username="alice") # par auteur (JOIN auto) # Créer, modifier, supprimer a = Article.objects.create(titre="Mon article", contenu="...") a.titre = "Nouveau titre"; a.save() a.delete()
10
L'interface Admin — automatique et puissante

L'un des atouts majeurs de Django : une interface d'administration complète générée automatiquement à partir des Models. En 2 lignes de code, tu as un backoffice professionnel.

# blog/admin.py from django.contrib import admin from .models import Article, Categorie # Enregistrement simple admin.site.register(Categorie) # Enregistrement personnalisé @admin.register(Article) class ArticleAdmin(admin.ModelAdmin): list_display = ['titre', 'auteur', 'publie_le', 'actif'] list_filter = ['actif', 'categorie'] search_fields = ['titre', 'contenu'] prepopulated_fields = {'slug': ('titre',)} # Créer un superutilisateur (en terminal) # python manage.py createsuperuser # Accès : http://127.0.0.1:8000/admin/
🎯 L'admin Django permet de gérer toutes tes données sans coder d'interface. C'est souvent suffisant pour les backoffices internes — et tu peux le personnaliser entièrement quand tu en as besoin.
🛡️ Sécurité Django — protégée par défaut
11
Django protège contre les attaques courantes

Django intègre par défaut les protections contre les principales vulnérabilités web — sans que tu aies à écrire une seule ligne de code de sécurité.

✅ CSRF Token anti-CSRF automatique sur tous les formulaires via {% csrf_token %}
✅ XSS L'auto-échappement des templates neutralise les balises HTML malveillantes.
✅ Injection SQL L'ORM utilise des requêtes paramétrées — jamais de SQL brut avec des données utilisateur.
✅ Mots de passe Hashage automatique (PBKDF2) — les mots de passe ne sont jamais stockés en clair.
