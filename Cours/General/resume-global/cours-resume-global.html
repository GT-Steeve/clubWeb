🧠 Module 01 — L'état d'esprit du développeur
01
L'état d'esprit du développeur

Ce module pose la fondation de tout le reste. La compétence technique ne suffit pas — la façon dont tu penses face à un problème détermine ta progression.

La formule fondamentale
Expertise = Temps passé à coder × Niveau de compréhension
Les deux facteurs sont indispensables. Passer du temps sans comprendre ne mène nulle part. Comprendre sans pratiquer non plus.
La vraie compétence d'un développeur n'est pas de mémoriser du code, c'est de comprendre le fonctionnement et de savoir lire la documentation.
Face à un blocage, trois ressources dans cet ordre : documentation officielle → Google/StackOverflow → IA.
Le cycle du développeur est une boucle infinie : Idée → Chercher → Coder → Tester → Analyser → Recommencer.
La passion et la curiosité ne se forcent pas mais s'entretiennent : ils accélèrent l'apprentissage plus que n'importe quel cours.

L'effet spaghetti — rappel essentiel

L'effet spaghetti est le piège central de tout le cours. Il se produit quand tu utilises de l'IA sans comprendre le code qu'elle génère.

Le mécanisme

→
IA → coller sans lire
→
Bug B + C apparaissent
↓

🔑 La règle absolue : comprendre avant de coller. Pas mémoriser — comprendre. Savoir ce que fait chaque ligne, pourquoi elle est là. C'est la seule protection durable contre le blocage de projet.

🏗️ Module 02 — Le HTML
02
Le HTML — Structure, balises & attributs

HTML (HyperText Markup Language) est le langage de structure du web. Il ne calcule rien, ne stylise rien — il décrit le contenu. Le CSS et le JavaScript travaillent ensuite sur cette base.

🏗️ HTML La structure — les murs, les pièces, les portes de ta page.
🎨 CSS Le style — la peinture, les meubles, la décoration.
⚙️ JavaScript Le comportement — l'électricité, les interrupteurs, la logique.
🌳 DOM L'arbre construit par le navigateur à partir du HTML.
Structure d'une balise
<balise attribut="valeur">contenu</balise>

Balises vides (auto-fermantes) : <img> <input> <br> <meta> <link> <hr>
📋
Les balises essentielles à retenir
Catégorie Balises clés Rôle
Structure page <!DOCTYPE> <html> <head> <body> Squelette obligatoire de toute page HTML
Sémantique <header> <nav> <main> <article> <section> <aside> <footer> Donnent du sens à la structure — remplacent les <div> génériques
Texte <h1-h6> <p> <strong> <em> <mark> <abbr> <code> Structure et mise en valeur du texte avec sens sémantique
Médias <img> <picture> <video> <audio> <figure> Intégration native de contenus visuels et sonores
Liens <a> avec href target rel download Navigation, téléchargement, mailto, tel
Formulaires <form> <input> <label> <select> <datalist> <fieldset> Saisie utilisateur — 15+ types d'input HTML5 natifs
Interactif <details> <summary> <dialog> Accordion et modale sans JavaScript
Attributs globaux id class data-* hidden tabindex contenteditable Disponibles sur toutes les balises — pont HTML/CSS/JS
⚠️ La règle d'or du HTML : utilise <div> uniquement pour les conteneurs de style sans signification. Pour tout le reste — il existe une balise sémantique.

🧩 Module 03 — Les Templates HTML/CSS/JS
03
Les Templates — Trouver, lire, personnaliser

Un template est un bloc de code HTML/CSS/JS déjà fonctionnel, conçu pour être réutilisé et adapté. Tout développeur professionnel s'appuie sur du code existant — la compétence, c'est savoir le lire, comprendre et adapter.

Lire tout le code avant de copier. Identifier la structure HTML, les classes CSS importantes, les dépendances JS.
Les variables CSS dans :root sont les premiers leviers de personnalisation — couleurs, polices, espacements.
Vérifier les Settings CodePen pour les librairies externes avant d'intégrer en local.
Un changement → un test. Ne pas tout modifier en même temps — impossible à déboguer.
Toujours vérifier la licence avant d'utiliser dans un projet commercial.
🛠️
La méthode complète en 5 étapes
1
Comprendre avant de modifier — Lire tout le HTML, CSS, JS. Identifier la structure et les classes importantes.
2
Variables CSS en premier — Le bloc :root dans le CSS. Couleurs, polices, espacements. Modification la plus sûre.
3
Remplacer le contenu — Textes, images, liens. Garder la structure HTML, changer uniquement le contenu.
4
Modifier la structure avec précaution — Ajouter ou retirer des éléments un par un. Tester après chaque changement.
5
Nettoyer — Supprimer ce dont tu n'as pas besoin. Un code léger est un code maintenable.

🔗 Les connexions entre les modules
🔗
Tout est lié — voilà comment

Ces trois modules ne sont pas indépendants. Ils forment un système cohérent de compétences qui se renforcent mutuellement.

🧠
L'état d'esprit (M01) conditionne tout. Sans la bonne façon de penser — curiosité, patience, méthode — les modules 02 et 03 ne s'ancrent pas correctement.
🏗️
Le HTML (M02) te donne les bases pour lire les templates. Impossible de comprendre et adapter un template si tu ne reconnais pas les balises et attributs qu'il utilise.
🧩
Les templates (M03) appliquent l'état d'esprit au HTML réel. Lire le code d'un template avant de l'utiliser, c'est exactement l'état d'esprit du M01 mis en pratique sur du vrai HTML/CSS.
🍝
L'effet spaghetti relie les 3 modules. Il se produit quand on ignore l'état d'esprit (M01), qu'on ne comprend pas le HTML (M02), et qu'on copie des templates sans les lire (M03).
La ligne directrice de tout le parcours
Comprendre avant d'agir. Que ce soit face à un bug, un nouveau concept HTML, ou un template trouvé sur CodePen — la même règle s'applique toujours : lire, comprendre, puis adapter. Jamais l'inverse.
