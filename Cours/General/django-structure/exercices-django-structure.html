Fichiers et rôles
manage.py↻
Le couteau suisse de Django — lance toutes les commandes : runserver, migrate, startapp…
settings.py↻
Le cerveau de la configuration — BDD, INSTALLED_APPS, langue, fichiers statiques…
urls.py projet↻
Point d'entrée de toutes les URLs — délègue aux apps via include()
urls.py app↻
Routes spécifiques à l'app — à créer manuellement, Django ne le génère pas
models.py↻
Décrit les tables de la BDD — chaque classe Python = une table SQL
views.py↻
Logique de chaque page — reçoit une requête, renvoie une réponse HTML
admin.py↻
Enregistre les models pour l'interface /admin/ — admin.site.register()
apps.py↻
Configuration de l'app — créé automatiquement, rarement modifié
migrations/↻
Historique complet des modifications de la BDD — ne jamais supprimer à la main
templates/↻
Fichiers HTML — chemin obligatoire : templates/nom_app/fichier.html
static/↻
CSS, JavaScript, images — chargés avec {% load static %} dans les templates
wsgi.py / asgi.py↻
Points d'entrée pour déployer en production — on n'y touche pas en développement

04 — Scénarios
Scénario 1
🧑‍💻 Vous venez de créer votre app avec python manage.py startapp blog. Vous essayez de faire une migration mais Django dit qu'il ne trouve aucun model. Que vérifiez-vous en premier ?
Que models.py n'est pas vide
Que 'blog' est bien dans INSTALLED_APPS dans settings.py
Que le serveur est bien lancé avec runserver
✓ Sans 'blog' dans INSTALLED_APPS, Django ignore complètement votre app — il ne voit ni vos models, ni vos templates, ni vos migrations.
Scénario 2
🧑‍💻 Vous avez créé une vue dans views.py et un template dans blog/templates/liste.html. Django affiche TemplateDoesNotExist. Où est le problème ?
Le template HTML contient une erreur de syntaxe
Le template est mal placé — il doit être dans blog/templates/blog/liste.html (sous-dossier obligatoire)
Il faut relancer le serveur pour que Django détecte le nouveau template
✓ Django cherche templates/blog/liste.html — le sous-dossier portant le nom de l'app est obligatoire pour éviter les conflits entre apps.
Scénario 3
🧑‍💻 Vous créez une route dans blog/urls.py mais la page affiche toujours une 404. Vous avez vérifié que la view existe. Que vérifiez-vous ?
Que monprojet/urls.py inclut bien include('blog.urls')
Que models.py n'a pas d'erreur de syntaxe
Que le fichier wsgi.py est correctement configuré
✓ Le urls.py de l'app doit être relié au urls.py du projet avec include(). Sans ça, Django ne connaît pas l'existence des routes de votre app.
Scénario 4
🧑‍💻 Vous modifiez un model dans models.py en ajoutant un champ. Vous rafraîchissez la page admin mais votre nouveau champ n'apparaît pas. Pourquoi ?
Il faut vider le cache du navigateur
Il faut re-enregistrer le model dans admin.py
Il faut lancer makemigrations puis migrate — la BDD n'a pas été mise à jour
✓ Modifier models.py ne suffit pas. Il faut toujours python manage.py makemigrations (crée la migration) puis python manage.py migrate (l'applique en BDD).
