1
Qu'est-ce qu'une base de données ?

Une base de données est un système organisé pour stocker, rechercher et modifier des informations de façon efficace. Chaque application web en a besoin : les utilisateurs, les articles, les commandes, les messages — tout est stocké en base de données.

Sans base de données, une application ne peut rien "se souvenir" entre deux visites. Elle est à l'application ce que le disque dur est à ton ordinateur.

Exemples concrets de données stockées
👤 Utilisateurs — nom, email, mot de passe hashé, rôle
📝 Articles / Posts — titre, contenu, date, auteur
🛒 Commandes — produits, quantités, prix, statut
💬 Messages — contenu, expéditeur, destinataire, date
📊 Logs & statistiques — visites, clics, temps passé

Les tables — la structure des données

Dans une base de données relationnelle, les données sont organisées en tables — comme des feuilles Excel. Chaque table a des colonnes (les champs) et des lignes (les enregistrements).

Vocabulaire fondamental
🔑 Clé primaire (PRIMARY KEY) — identifiant unique de chaque ligne (souvent id)
🔗 Clé étrangère (FOREIGN KEY) — lien vers la clé primaire d'une autre table
📋 Schéma — la structure de la base (quelles tables, quelles colonnes)
📝 Requête — une instruction pour lire ou modifier les données
3
Le SQL — parler à la base de données

SQL (Structured Query Language) est le langage universel des bases de données relationnelles. Ses 4 opérations fondamentales forment le CRUD :

-- CREATE : créer une table CREATE TABLE utilisateurs ( id INT PRIMARY KEY AUTO_INCREMENT, nom VARCHAR(100) NOT NULL, email VARCHAR(150) UNIQUE NOT NULL, age INT, actif BOOLEAN DEFAULT TRUE ); -- READ : lire des données SELECT * FROM utilisateurs; SELECT nom, email FROM utilisateurs WHERE actif = TRUE; SELECT * FROM utilisateurs WHERE age > 25 ORDER BY nom; -- CREATE (INSERT) : insérer une ligne INSERT INTO utilisateurs (nom, email, age) VALUES ('Alice', 'alice@mail.com', 28); -- UPDATE : modifier des données UPDATE utilisateurs SET age = 29 WHERE id = 1; -- DELETE : supprimer DELETE FROM utilisateurs WHERE id = 3;
⚠️ Toujours utiliser WHERE avec UPDATE et DELETE. Sans WHERE, tu modifies ou supprimes toutes les lignes — l'erreur la plus redoutée des développeurs.
🔗 Les relations entre tables
4
Les relations — relier les tables entre elles

La puissance des bases relationnelles vient des relations entre tables. On évite la duplication — on stocke une information une seule fois et on y fait référence ailleurs.

Exemple : blog avec auteurs et articles
📋 Table : utilisateurs
🔑 id INT PRIMARY KEY
nom VARCHAR(100)
email VARCHAR(150)
📋 Table : articles
🔑 id INT PRIMARY KEY
titre VARCHAR(200)
contenu TEXT
🔗 utilisateur_id INT FOREIGN KEY → utilisateurs.id
-- JOIN : joindre deux tables -- Récupérer les articles avec le nom de leur auteur SELECT articles.titre, utilisateurs.nom AS auteur FROM articles JOIN utilisateurs ON articles.utilisateur_id = utilisateurs.id; -- Résultat : -- | titre | auteur | -- | Mon premier post | Alice Dupont | -- | Introduction au SQL| Bob Martin |
Les 3 types de relations
1:1 — Un utilisateur a un seul profil (profil ↔ utilisateur)
1:N — Un auteur a plusieurs articles (auteur ↔ articles) — le plus courant
N:M — Un article peut avoir plusieurs tags, un tag peut être sur plusieurs articles → table de jonction nécessaire
🛢️ Les systèmes de bases de données
5
MySQL vs PostgreSQL — lesquels utiliser ?

SQL est le langage — mais il faut aussi choisir le système de gestion de base de données (SGBD) qui l'implémente.

🐬 MySQL Le plus répandu. Simple à installer, rapide, utilisé par WordPress, Facebook (anciennement). Idéal pour débuter.

Utilisé par : WordPress, Joomla, Drupal
🐘 PostgreSQL Plus avancé et plus strict. Supporte des types de données complexes (JSON, arrays…). Recommandé pour les projets sérieux.

Utilisé par : Django (recommandé), Instagram, Heroku
🎯 Pour apprendre : commence avec MySQL ou SQLite (SQLite ne nécessite même pas d'installation — Django l'utilise par défaut). Pour la production avec Django : PostgreSQL est la référence.
6
NoSQL — quand SQL ne suffit pas

Les bases NoSQL (Not Only SQL) sont conçues pour des cas d'usage où la structure tabulaire est inadaptée : données non structurées, très grande quantité, temps réel.

🍃 MongoDB (documents) Stocke des documents JSON. Flexibilité maximale — pas de schéma fixe. Utilisé pour des données variables.
⚡ Redis (clé-valeur) Ultra-rapide, stocke en mémoire. Utilisé pour le cache, les sessions, le temps réel.
SQL vs NoSQL — quand choisir ?
✅ SQL — données structurées avec relations (blog, e-commerce, CRM, ERP)
✅ MongoDB — données variables, JSON imbriqué (catalogues, logs, contenus)
✅ Redis — cache, sessions, données temps réel (notifications, leaderboards)
🔄 L'ORM — plus de SQL brut
7
L'ORM — manipuler la BDD avec des objets

Un ORM (Object-Relational Mapper) permet d'interagir avec la base de données en utilisant des objets du langage de programmation, sans écrire de SQL brut. Django et Laravel ont chacun leur ORM.

-- SQL brut (sans ORM) SELECT * FROM articles WHERE actif = 1 ORDER BY date DESC LIMIT 10; # Django ORM (équivalent Python) Article.objects.filter(actif=True).order_by('-date')[:10] // Laravel Eloquent (équivalent PHP) Article::where('actif', 1)->orderBy('date', 'desc')->take(10)->get();
💡 L'ORM offre aussi les migrations : des fichiers qui décrivent l'évolution du schéma de ta base de données. Chaque modification de structure se fait via une migration — et peut être annulée.
