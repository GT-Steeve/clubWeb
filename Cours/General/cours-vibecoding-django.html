00 — C'est quoi le vibecoding ?
?
Définition

Le vibecoding (ou « coder à l'instinct avec l'IA ») est une façon de programmer où tu décris ce que tu veux en langage naturel à une IA, et tu assembles le code qu'elle génère pour construire ton projet. Tu n'écris pas tout depuis zéro — tu guides, testes, corriges et assembles.

« There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists. » — Andrej Karpathy, co-fondateur d'OpenAI, février 2025

En pratique : tu parles à ChatGPT, Claude ou Copilot comme à un développeur senior. Tu lui décris une fonctionnalité, il génère le code, tu l'intègres dans ton projet, tu testes, et tu continues.

💡 Le vibecoding n'est pas de la triche — c'est une compétence. Savoir écrire de bons prompts, évaluer le code généré et l'assembler correctement est une vraie maîtrise professionnelle. Les développeurs seniors l'utilisent tous les jours.

01 — Avantages & inconvénients
⚖️
Ce que le vibecoding change — pour le meilleur et pour le pire
✅ Avantages
🚀Vitesse. Un formulaire Django qui prendrait 2 heures seul ? 10 minutes avec l'IA.
🧠Apprendre en faisant. On lit le code généré, on comprend la syntaxe en contexte réel.
🔓Débloquer rapidement. L'IA connaît la documentation — fini de chercher pendant 1h sur Stack Overflow.
🎯Se concentrer sur l'idée. Tu penses au produit, pas à la syntaxe.
♻️Prototyper vite. Tester une idée en quelques minutes avant de s'investir.
🌍Accessible. Un débutant peut créer des choses qui auraient nécessité des mois de formation.
❌ Inconvénients
🕳️Code qu'on ne comprend pas. Risque de copier sans savoir ce que ça fait.
🐛Bugs invisibles. L'IA fait des erreurs subtiles difficiles à détecter sans bases solides.
🔒Sécurité. Le code généré peut avoir des failles (SQL injection, secrets exposés…).
🍝Code spaghetti. Sans architecture, le projet devient vite ingérable.
📦Dépendance. Sans comprendre, on ne peut pas corriger seul quand l'IA échoue.
🔄Boucles infinies. On peut rester bloqué à corriger du code incompris.
🎯 La règle d'or — Ne colle jamais du code que tu ne peux pas lire et expliquer ligne par ligne. Si tu ne comprends pas, demande à l'IA d'expliquer avant d'intégrer.
02 — Les 3 niveaux du vibecoder
📊
Comment progresser avec le vibecoding

Le vibecoding n'est pas un état fixe — c'est un spectre. Plus tu montes en compétences, plus tu utilises l'IA intelligemment.

🤖 Niveau 1 — Vibe pur 🧑‍💻 Niveau 2 — Dev assisté 🏗️ Niveau 3 — Architecte IA
NiveauCe que tu faisRisque
Niveau 1
Vibe pur		 Tu copies le code sans le lire. L'IA fait tout. 🔴 Très élevé — tu ne comprends rien, tu ne peux pas déboguer.
Niveau 2
Dev assisté		 Tu lis le code, tu poses des questions, tu adaptes. L'IA accélère. 🟡 Modéré — tu apprends activement.
Niveau 3
Architecte IA		 Tu conçois l'architecture, l'IA remplit les détails. Tu valides tout. 🟢 Faible — tu es en contrôle total.
🎯 L'objectif de ce cours est de t'emmener au Niveau 2 rapidement, puis de progresser vers le Niveau 3 naturellement en pratiquant.
03 — Écrire un bon prompt de code
💬
La structure d'un prompt efficace

La qualité du code généré dépend directement de la qualité de ta question. Un bon prompt de code contient 4 éléments :

Structure d'un prompt de code
1. Le contexte — quel projet, quel langage, quel framework
2. Ce que tu veux faire — la fonctionnalité précise
3. Les contraintes — ce qui existe déjà, ce qu'il ne faut pas casser
4. Le format attendu — fichier complet, snippet, explication incluse
❌ Mauvais prompt Trop vague
Prompt utilisateur
> fais moi un formulaire django

Ce prompt donne un résultat générique. L'IA ne sait pas quel model, quel champ, quelle vue, quel template — elle invente tout et rien ne correspondra à ton projet.

✅ Bon prompt Contexte + besoin + contraintes
Prompt utilisateur
> Je travaille sur un projet Django 5. J'ai un model Article avec les champs : - titre (CharField, max 200) - contenu (TextField) - publie (BooleanField, default False) Génère-moi un ModelForm pour créer un article, la vue qui le gère (create + redirect vers la liste), et le template HTML qui étend "base.html". Inclus {% csrf_token %} dans le formulaire. Commente chaque partie pour que je comprenne.
✨ Ce prompt donne à l'IA tout ce dont elle a besoin : le model existant, la fonctionnalité voulue, les fichiers à générer, et la demande d'explication.
📝
Formules de prompts à réutiliser
SituationFormule de prompt
Débuter une fonctionnalitéJe veux ajouter [fonctionnalité] à mon projet Django. Mon model ressemble à [coller le model]. Génère la vue, le template et l'URL.
Corriger une erreurJ'ai cette erreur : [coller l'erreur]. Voici mon code : [coller le code]. Explique pourquoi et corrige-le.
Comprendre du codeExplique-moi ce code ligne par ligne comme si j'étais débutant en Django : [coller le code]
Améliorer du code existantVoici ma vue Django : [code]. Améliore-la pour [ajouter pagination / sécuriser / optimiser la requête ORM].
Générer des données de testGénère un script Python pour créer 10 articles de test dans ma BDD Django avec des données réalistes.
04 — Comment assembler du code généré par l'IA
🔧
La méthode en 5 étapes

Recevoir du code de l'IA ne suffit pas. Il faut l'intégrer intelligemment dans ton projet sans tout casser.

Lire avant de collerParcourir le code généré. Identifier les imports, les noms de classes, les chemins. Repérer ce que tu ne comprends pas.
Vérifier les dépendancesL'IA a-t-elle importé quelque chose qui n'existe pas dans ton projet ? Un model qui ne s'appelle pas pareil ? Une variable de contexte différente ?
Adapter au contexteRenommer les variables si besoin, ajuster les chemins de templates, corriger les noms d'URL pour correspondre à ton urls.py.
Tester immédiatementColler, sauvegarder, lancer le serveur, tester dans le navigateur. Ne pas attendre d'avoir tout intégré pour tester.
Corriger en boucleSi erreur → copier le message d'erreur complet → le donner à l'IA → appliquer la correction → retester. Répéter jusqu'à ce que ça marche.
🔍 Exemple concret — intégrer une vue de création Fil rouge Blog

L'IA génère ce code. Voici comment le lire et l'intégrer étape par étape.

Ce que l'IA génère

blog/forms.py — généré par l'IA 
from django import forms
from .models import Article  # ← vérifier : Article existe bien dans models.py ?

class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article           # ← même nom que dans models.py ?
        fields = ['titre', 'contenu', 'publie']  # ← champs corrects ?
blog/views.py — à ajouter 
from django.shortcuts import render, redirect
from .forms import ArticleForm   # ← le fichier forms.py existe ?

def creer_article(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect('blog:liste')  # ← 'blog:liste' existe dans urls.py ?
    else:
        form = ArticleForm()
    return render(request, 'blog/creer_article.html', {'form': form})
🔍 Lis les commentaires en orange — ce sont les 3 questions à te poser avant de coller du code IA. Si une réponse est non, corrige avant d'intégrer.

Le template généré

blog/templates/blog/creer_article.html 
{% extends "base.html" %}  <!-- base.html existe à la racine ? -->

{% block contenu %}
<h1>Créer un article</h1>
<form method="post">
    {% csrf_token %}   <!-- obligatoire pour les formulaires POST -->
    {{ form.as_p() }}    <!-- affiche chaque champ dans un <p> -->
    <button type="submit">Publier</button>
</form>
{% endblock %}
05 — Faire fonctionner plusieurs morceaux ensemble
🧩
Le problème de l'assemblage

L'IA génère souvent des morceaux de code séparés. La difficulté est de les faire communiquer ensemble. En Django, un flux complet nécessite que 4 fichiers se parlent :

forms.py
Formulaire
→
views.py
Logique
→
urls.py
Route
→
template.html
Affichage

Chaque fichier doit référencer les bons noms des autres. C'est là que l'assemblage peut planter.

⚡ Checklist d'assemblage Avant de tester

Avant de lancer le serveur après avoir intégré du code IA, vérifie ces points :

Quoi vérifierExemple concret
Noms des modelsL'IA a écrit Article — ton model s'appelle bien Article dans models.py ?
Noms des vues dans urls.pyredirect('blog:liste') → la vue liste existe bien dans blog/urls.py ?
Chemin du template'blog/creer_article.html' → le fichier est bien dans blog/templates/blog/ ?
Noms des champs du formfields = ['titre', 'contenu'] → ces champs existent dans le model ?
Imports manquantsL'IA a utilisé get_object_or_404 sans l'importer ?
{% load static %}Si le template utilise {% static %}, la ligne {% load static %} est en haut ?
MigrationsSi l'IA a modifié models.py, as-tu lancé makemigrations et migrate ?
06 — Déboguer avec l'IA
🐛
L'IA comme partenaire de débogage

Quand une erreur arrive après avoir intégré du code IA, ne la googler pas directement — colle-la à l'IA avec son contexte. C'est l'un des meilleurs usages du vibecoding.

🔴 Erreur Django Comment la traiter

L'erreur apparaît dans le navigateur

Erreur Django — page de debug 
NoReverseMatch at /blog/creer/
Reverse for 'liste' not found. 'liste' is not a valid view
function or pattern name.

Le prompt idéal pour la corriger

Prompt à copier-coller
J'ai cette erreur Django : NoReverseMatch at /blog/creer/ Reverse for 'liste' not found. Voici mon views.py : [coller le code de la vue] Voici mon blog/urls.py : [coller le contenu du fichier urls.py] Explique-moi pourquoi et comment corriger.
🎯 Toujours coller les 3 éléments : le message d'erreur exact + le code fautif + les fichiers liés. Sans contexte, l'IA ne peut pas deviner la cause réelle.
⚠️
Quand l'IA se trompe — et comment le détecter

L'IA peut générer du code qui semble correct mais qui ne l'est pas. Voici les cas les plus fréquents en Django :

Erreur courante de l'IAComment la repérer
Utiliser Django 3.x alors que tu es en 4.x ou 5.xLes imports peuvent changer. Vérifier la doc Django officielle.
Inventer des noms de champs ou de variablesComparer avec ton models.py réel.
Oublier {% csrf_token %} dans les formulairesToujours vérifier dans le template avant de tester.
Mettre la logique dans le template au lieu de la vueSignal d'alarme : beaucoup de code Python dans le HTML.
Générer du code qui expose des secretsNe jamais coller une SECRET_KEY ou un mot de passe dans un fichier versionné.
🚨 L'IA hallucine parfois — elle peut inventer une fonction Django qui n'existe pas, avec une syntaxe qui a l'air correcte. Si quelque chose te semble bizarre, vérifie toujours sur docs.djangoproject.com.

08 — Les règles d'or du vibecoder
✓
Ce qu'un bon vibecoder fait toujours
Il lit avant de collerJamais de code aveugle. Lire, même en diagonale, permet de repérer les incohérences avec le projet existant.
Il demande des explicationsAprès chaque génération : « Explique-moi ce que fait cette partie ». Comprendre est plus important qu'avancer vite.
Il teste petits morceauxIl n'intègre pas 5 fichiers d'un coup avant de tester. Un fichier → test → validation → suivant.
Il versionne avec GitAvant d'intégrer du code IA, un git commit. Si ça plante, un git stash pour revenir en arrière.
Il ne cache pas les secretsJamais de SECRET_KEY, mot de passe ou clé API dans le code versionné — même généré par l'IA.
Il donne le contexte complet à l'IAPlus le prompt est précis (model existant, erreur exacte, fichiers liés), meilleur est le résultat.
