Concepts clés du vibecoding
Qu'est-ce que le vibecoding ?↻
Coder en décrivant ses besoins à une IA en langage naturel, puis assembler et adapter le code généré.
Qui a inventé le terme « vibecoding » ?↻
Andrej Karpathy, co-fondateur d'OpenAI, en février 2025.
Les 4 éléments d'un bon prompt de code↻
1. Le contexte (projet, langage)
2. Ce que tu veux faire
3. Les contraintes
4. Le format attendu
Le plus grand danger du vibecoding↻
Copier du code sans le comprendre — si ça plante, on est incapable de déboguer seul.
Que faire avant de coller du code IA ?↻
Le lire, vérifier les imports, les noms de variables et les références au projet existant.
Qu'est-ce qu'une hallucination de l'IA ?↻
Quand l'IA invente une fonction ou une syntaxe qui n'existe pas, avec l'air parfaitement confiant.
Quoi faire quand on a une erreur Django ?↻
Coller à l'IA : l'erreur exacte + le code fautif + les fichiers liés (views.py, urls.py…).
La règle avant d'intégrer du code IA↻
Faire un git commit avant — pour pouvoir revenir en arrière si le code génère une régression.
Ce qu'on ne doit jamais faire avec le vibecoding↻
Mettre une SECRET_KEY, un mot de passe ou une clé API dans un fichier versionné sur Git.
Les 3 niveaux du vibecoder↻
1. Vibe pur (copie sans lire)
2. Dev assisté (lit + adapte)
3. Architecte IA (conçoit, l'IA remplit)

04 — Scénarios — que faites-vous ?
Scénario 1
🧑‍💻 L'IA te génère une vue Django complète. Tu la colles dans views.py, tu lances le serveur et tu obtiens : NameError: name 'Article' is not defined. Que fais-tu ?
Demander à l'IA de régénérer un code différent
Vérifier que l'import from .models import Article est bien présent en haut du fichier views.py
Supprimer le fichier views.py et recommencer depuis zéro
✓ Un NameError sur un nom de model signale presque toujours un import manquant. L'IA génère parfois le code sans inclure toutes les lignes d'import nécessaires — vérification systématique en haut du fichier.
Scénario 2
🧑‍💻 Tu demandes à l'IA un formulaire Django pour ton model Produit. Elle génère un form avec fields = ['name', 'price', 'stock']. Mais dans ton models.py, les champs s'appellent nom, prix et quantite. Que fais-tu ?
Renommer tous les champs de ton model pour correspondre au code IA
Coller le form tel quel et voir si ça marche quand même
Adapter le code IA : remplacer 'name' par 'nom', 'price' par 'prix', etc. pour correspondre à ton vrai model
✓ L'IA ne connaît pas exactement ton projet — elle devine les noms. C'est ton rôle d'adapter ses noms génériques aux vrais noms de ton code. Toujours comparer avec ton models.py avant d'intégrer.
Scénario 3
🧑‍💻 L'IA t'a aidé à coder une belle fonctionnalité. Tout fonctionne. Elle te suggère maintenant d'ajouter directement la variable DATABASE_URL = "postgres://user:monmotdepasse@host/db" dans ton fichier settings.py que tu vas commiter sur GitHub. Que fais-tu ?
Coller la variable dans settings.py et faire le commit — ça simplifie la configuration
Refuser — mettre cette valeur dans un fichier .env non versionné et utiliser python-decouple ou os.environ pour la lire
Mettre la variable dans un commentaire pour qu'elle ne soit pas lue
✓ Un mot de passe ou une URL de base de données dans un repo Git public (ou même privé partagé) est une faille de sécurité majeure. L'IA peut suggérer des pratiques peu sécurisées — c'est toi qui décides. Toujours utiliser des variables d'environnement pour les secrets.
Scénario 4
🧑‍💻 Tu es bloqué depuis 30 minutes sur une erreur Django. L'IA t'a proposé 3 corrections différentes, aucune n'a fonctionné, et maintenant le code est un mélange des 3 suggestions. Que fais-tu ?
Continuer à demander à l'IA des corrections jusqu'à ce que ça marche
Faire un git stash pour revenir à l'état qui fonctionnait, puis repartir proprement avec un nouveau prompt qui donne à l'IA l'erreur exacte + tout le code concerné
Tout supprimer et recommencer le projet depuis zéro
✓ Quand on accumule des corrections IA sans comprendre, le code devient incontrôlable. Git est ton filet de sécurité. Revenir en arrière, repartir proprement avec un prompt précis vaut mieux qu'accumuler des patchs incompris.

06 — Remettre dans l'ordre
↕️
Le cycle d'intégration de code IA dans un projet Django

Glissez-déposez ces étapes dans l'ordre logique.

⠿? Copier le code dans le bon fichier du projet
⠿? Écrire un prompt précis avec contexte + besoin + contraintes
⠿? Tester dans le navigateur
⠿? Lire le code généré et vérifier les imports et les noms
⠿? Si erreur : coller l'erreur à l'IA avec le contexte et corriger
⠿? Faire un git commit pour sauvegarder l'état actuel
⠿? Adapter le code au contexte réel (noms des champs, URL, template)
Ordre correct
Étape 1git commit (sauvegarde)
Étape 2Écrire un bon prompt
Étape 3Lire le code généré
Étape 4Copier dans le projet
Étape 5Adapter au contexte réel
Étape 6Tester dans le navigateur
Étape 7Si erreur : corriger avec l'IA
