🛠️ Projet — Mon idée de création

Choisis un projet, planifie-le, lance-le. C'est en créant qu'on apprend vraiment.

Planification MVP Git
🎯
Objectif du projet

Tu as appris à planifier, itérer et t'organiser. Maintenant, c'est le moment de choisir un vrai projet et de le démarrer.

Ce projet n'est pas un exercice avec une réponse attendue — c'est ton projet, ta création. Il n'a pas besoin d'être impressionnant. Il doit exister et fonctionner.

💡 Un timer Pomodoro terminé vaut mieux qu'un RPG multijoueur inachevé. Commence petit, finis, puis améliore.
🗂️
Étape 1 — Choisir ton type de projet

Quel type de création correspond à ce que tu veux faire ? Choisis l'un de ces types comme point de départ :

🔧 Outil utile
Timer, calculateur, convertisseur, générateur de citations...
🎮 Jeu simple
Casse-briques, snake, quiz chronométré, memory...
🧩 Énigme / défi
Quiz de logique, escape game web, devinettes...
🌐 Site vitrine
Page pour un club, un ami, un événement fictif...
Ta fiche idée — à compléter mentalement ou sur papier :
→Type choisi : outil / jeu / énigme / site
→Mon idée en une phrase : "Je veux créer un(e) _____ qui permet de _____"
→Technos que j'utiliserai : HTML, CSS, JS, Canvas…
→Est-ce faisable avec ce que je sais faire ? ✅ / ⚠️ (trop ambitieux)
📋
Étape 2 — Planifier ton MVP

Ton MVP (version 1 minimale) doit fonctionner sur le cas principal, rien de plus. Sépare clairement ce qui est dans la v1 et ce qui attendra la v2.

1
Lister toutes les fonctionnalités imaginées — sans te censurer.
2
Identifier la fonctionnalité principale — celle sans laquelle le projet ne sert à rien.
3
Mettre tout le reste en v2 ou v3 — si ce n'est pas indispensable pour que ça fonctionne, ça attend.
4
Décomposer la v1 en tâches concrètes — chaque tâche doit être faisable en moins d'une session.
⚠️ Exemple — Timer Pomodoro : v1 = afficher un compte à rebours de 25 min avec un bouton Start/Stop. V2 = sons, historique, personnalisation.
🗃️
Étape 3 — Lancer le projet avec Git

Dès le premier fichier créé, initialise Git. C'est une habitude professionnelle à prendre dès le début, pas à la fin.

1
Crée un dossier pour ton projet et ouvre-le dans VS Code.
2
Dans le terminal : git init puis crée ton premier fichier index.html.
3
Premier commit : git add . && git commit -m "init projet"
4
Fais un commit à chaque tâche terminée — pas à chaque ligne de code.
💡 Rédige des patch-notes dans un fichier CHANGELOG.md : "v0.1 — Structure HTML de base. v0.2 — Compte à rebours fonctionnel."
✅
Ce que doit contenir ton projet v1
✅ Un titre et une description du projet clairement visible dans la page.
✅ La fonctionnalité principale fonctionnelle — ce à quoi le projet sert vraiment.
✅ Un design minimal mais propre — lisible, sans erreur d'affichage évidente.
✅ Un dépôt Git avec au moins 3 commits qui montrent la progression.
✅ Le projet s'ouvre dans le navigateur sans erreur console.
🌟 Un fichier CHANGELOG.md avec les versions et ce qu'elles apportent.
🌟 Une liste de fonctionnalités v2 notée dans un TODO.md.
🌟 Montrer le projet à quelqu'un et noter un retour pour la v2.
☑️
Checklist de validation

Coche chaque étape au fur et à mesure :

J'ai choisi mon type de projet (outil / jeu / énigme / site)
J'ai décrit mon idée en une phrase claire
J'ai défini mon MVP et mis le reste en v2
J'ai décomposé la v1 en tâches concrètes
J'ai initialisé un dépôt Git dès le départ
La fonctionnalité principale fonctionne
Le projet s'ouvre sans erreur dans le navigateur
J'ai au moins 3 commits qui montrent la progression
J'ai montré le projet à quelqu'un et noté un retour
