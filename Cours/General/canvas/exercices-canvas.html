🎭 Scénarios — Débogage de jeu
Scénario 1
🎮 Ton joueur se déplace, mais il laisse une traînée orange derrière lui. L'écran ressemble à une peinture abstraite. Quelle est la cause ?
Le joueur se déplace trop vite — il faut réduire sa vitesse
ctx.clearRect() n'est pas appelé à chaque frame — les anciens dessins s'accumulent sur le canvas
Il faut utiliser ctx.fillStyle = 'transparent' avant chaque dessin
✓ Sans clearRect(0, 0, canvas.width, canvas.height) au début de chaque frame, les dessins précédents ne sont pas effacés. Le canvas s'accumule et laisse une traînée.
Scénario 2
🎮 Ton joueur peut sauter autant de fois qu'il veut en maintenant la touche espace, même en l'air. Il monte à l'infini. Comment corriger ça ?
Réduire la valeur de FORCE_SAUT
Supprimer l'événement keydown après le premier saut
Vérifier joueur.auSol === true avant d'appliquer FORCE_SAUT — le saut n'est autorisé que depuis le sol
✓ Il faut conditionner le saut : if (touches[' '] && joueur.auSol). La variable auSol passe à false au saut et revient à true lors de l'atterrissage sur une plateforme.
Scénario 3
🎮 Ton joueur bouge avec les flèches, mais le mouvement est saccadé : il y a un délai au démarrage, puis ça accélère. C'est irritant à jouer. Quelle est l'erreur ?
Le joueur est déplacé directement dans l'événement keydown — il faut mémoriser les touches dans un objet et les lire dans la game loop
Le canvas est trop grand — ça ralentit les performances
Il faut utiliser setInterval à la place de requestAnimationFrame
✓ keydown a un délai de répétition système (OS). La bonne approche : touches[e.key] = true dans keydown, false dans keyup, et lire touches dans la game loop à chaque frame.
