Suite de : projet-django-crud.html — tu as un blog CRUD fonctionnel.
Objectif : Ajouter un système d'inscription et de connexion — seuls les utilisateurs connectés peuvent créer, modifier ou supprimer des articles.
Progression 0 / 6 étapes
1
Brancher les URLs Django Auth
▾

Django fournit des vues prêtes à l'emploi pour la connexion et la déconnexion. Il suffit d'inclure leurs URLs dans ton projet.

monprojet/urls.py — ajouter
from django.contrib import admin from django.urls import path, include urlpatterns = [ path('admin/', admin.site.urls), path('blog/', include('blog.urls')), path('accounts/', include('django.contrib.auth.urls')), path('accounts/inscription/', blog_views.inscription, name='inscription'), ]
💡
django.contrib.auth.urls fournit automatiquement les routes pour /accounts/login/, /accounts/logout/, changement de mot de passe, etc.
monprojet/settings.py — ajouter en bas
# Redirections après login/logout LOGIN_REDIRECT_URL = 'blog:index' LOGOUT_REDIRECT_URL = 'blog:index'
2
Template de connexion
▾

Django cherche le template de connexion dans templates/registration/login.html. Crée ce dossier et ce fichier.

templates/registration/login.html
{% extends 'blog/base.html' %} {% block title %}Connexion{% endblock %} {% block content %} <h1>🔑 Connexion</h1> <form method="post"> {% csrf_token %} {{ form.as_p }} <button type="submit">Se connecter</button> </form> <p>Pas encore de compte ? <a href="{% url 'inscription' %}">S'inscrire</a> </p> {% endblock %}
📂
Le dossier registration/ doit se trouver dans un dossier templates/ visible par Django — vérifie que TEMPLATES[0]['DIRS'] inclut le bon chemin dans settings.py.
3
Vue d'inscription avec UserCreationForm
▾

Django fournit UserCreationForm — un formulaire prêt à l'emploi pour créer un compte utilisateur avec validation des mots de passe.

blog/views.py — ajouter
from django.contrib.auth.forms import UserCreationForm from django.contrib.auth import login def inscription(request): if request.method == 'POST': form = UserCreationForm(request.POST) if form.is_valid(): user = form.save() login(request, user) # connexion automatique après inscription return redirect('blog:index') else: form = UserCreationForm() return render(request, 'registration/inscription.html', {'form': form})
templates/registration/inscription.html
{% extends 'blog/base.html' %} {% block title %}Inscription{% endblock %} {% block content %} <h1>📝 Créer un compte</h1> <form method="post"> {% csrf_token %} {{ form.as_p }} <button type="submit">Créer mon compte</button> </form> <p>Déjà un compte ? <a href="{% url 'login' %}">Se connecter</a></p> {% endblock %}
✨
login(request, user) connecte automatiquement l'utilisateur après son inscription — pas besoin de le rediriger vers la page de connexion.
4
Protéger les vues avec @login_required
▾

Le décorateur @login_required redirige automatiquement vers la page de connexion si l'utilisateur n'est pas authentifié. Ajoute-le sur toutes les vues d'écriture.

blog/views.py — vérification des décorateurs
from django.contrib.auth.decorators import login_required @login_required ✓ déjà présent depuis le projet CRUD def creer_article(request): ... @login_required ✓ def modifier_article(request, pk): ... @login_required ✓ def supprimer_article(request, pk): ...
monprojet/settings.py — configurer la redirection
# Quand @login_required redirige vers la connexion LOGIN_URL = 'login' # nom de l'URL de connexion fournie par auth.urls
🔒
Sans LOGIN_URL, Django utilise /accounts/login/ par défaut — qui correspond à l'URL incluse via django.contrib.auth.urls. Dans la plupart des cas, aucune configuration supplémentaire n'est nécessaire.
5
Navigation dynamique dans base.html
▾

La variable user est disponible dans tous les templates Django. Affiche des liens différents selon l'état de connexion.

templates/blog/base.html — barre de navigation
<nav> <a href="{% url 'blog:index' %}">🏠 Accueil</a> {% if user.is_authenticated %} <a href="{% url 'blog:creer' %}">✍️ Écrire</a> <span>👤 {{ user.username }}</span> <form method="post" action="{% url 'logout' %}" style="display:inline"> {% csrf_token %} <button type="submit">Déconnexion</button> </form> {% else %} <a href="{% url 'login' %}">Connexion</a> <a href="{% url 'inscription' %}">Inscription</a> {% endif %} </nav>
💡
user.is_authenticated retourne True si l'utilisateur est connecté. user.username affiche son nom. La déconnexion passe par un formulaire POST depuis Django 5.x.
6
Vérification finale — le projet complet
▾

Lance le serveur et teste l'ensemble du flux d'authentification sur ton blog.

🎯 Checklist de validation

  • Visite /accounts/inscription/ → crée un compte → tu es connecté automatiquement
  • Visite /blog/article/creer/ → tu vois le formulaire (car connecté)
  • Déconnecte-toi → essaie de visiter /blog/article/creer/ → redirigé vers la connexion
  • Reconnecte-toi avec tes identifiants
  • Crée un article → les boutons Modifier/Supprimer sont visibles uniquement pour toi
  • La nav affiche ton username quand connecté, les liens Connexion/Inscription sinon
