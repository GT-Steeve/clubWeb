Phaser.js & Solar2D

Découvre deux frameworks dédiés aux jeux 2D : l'un pensé pour le web, l'autre pour le mobile — deux approches, deux philosophies.

Phaser.js Solar2D JavaScript · Lua Culture
Section 1
🤔
Pourquoi un moteur dédié 2D ?

Unreal Engine, Unity et Godot peuvent tous faire du 2D. Alors pourquoi utiliser un framework dédié ? La réponse : légèreté, focus et contexte de déploiement.

Un moteur 3D complet qui fait du 2D, c'est comme utiliser un semi-remorque pour faire des courses au coin de la rue — ça marche, mais c'est surdimensionné. Les frameworks 2D sont pensés dès le départ pour un contexte précis :

Framework 2D dédié
Léger, rapide à démarrer, API pensée pour la 2D, parfaitement adapté à son contexte (web ou mobile).
Moteur généraliste en mode 2D
Lourd à installer, concepts 3D pas toujours pertinents, courbe d'apprentissage plus longue.
💡
Le canvas HTML5 que tu as appris, c'est la couche la plus basse : tu dessines toi-même tout pixel par pixel. Phaser.js est construit par-dessus le canvas — il gère les sprites, la physique et les scènes pour toi.
Section 2
⚡
Phaser.js

Phaser est un framework de jeu 2D pour le navigateur web, créé en 2013 par Richard Davey (alias Photonstorm). Il est écrit en JavaScript/TypeScript et tourne directement dans le navigateur — sans installation pour le joueur.

⚡
Phaser.js — v3
Photonstorm · depuis 2013 · JavaScript / TypeScript · MIT
Rendu — Canvas 2D ou WebGL (accélération GPU dans le navigateur)
Physique — Arcade (légère, parfaite pour platformers) ou Matter.js (réaliste)
Scènes — système de scènes stackables (menu, jeu, pause, game-over simultanés)
Sprites — animations frame-by-frame depuis des spritesheets intégrées

Mini-jeux BBC / Disney Jeux HTML5 mobiles Game jams web Jeux éducatifs
Points forts
Tourne dans le navigateur, zéro installation joueur, JavaScript que tu connais, énorme documentation et communauté.
Points faibles
Performance mobile limitée vs natif, export app store via Cordova (complexe), pas de 3D.
Exemple de config Phaser
const config = { type: Phaser.AUTO, // Canvas ou WebGL selon le navigateur width: 800, height: 600, physics: { default: 'arcade', // moteur physique léger arcade: { gravity: { y: 300 }, debug: false } }, scene: [PreloadScene, MenuScene, GameScene] // liste de scènes }; const game = new Phaser.Game(config);
🌐
Phaser est le framework de référence pour les game jams web (Ludum Dare, itch.io). Ton jeu s'ouvre dans n'importe quel navigateur — partage un lien, c'est jouable immédiatement.
Section 3
🌙
Solar2D

Solar2D (anciennement Corona SDK) est un framework de jeu 2D pensé pour le mobile (iOS & Android). Créé en 2009 par Walter Luh, il a été rendu open source en 2020 après le rachat raté de Corona Labs.

🌙
Solar2D (ex Corona SDK)
Open Source · depuis 2009 · Lua · MIT (depuis 2020)
Lua — langage de script léger et rapide, très populaire dans le jeu vidéo (aussi utilisé dans Roblox, Love2D)
Natif mobile — rendu via le GPU du téléphone, performances quasi natives
Simulateur intégré — teste ton jeu directement sur ton PC avant de déployer
Plugins — accès aux APIs mobiles (caméra, gyroscope, notifications push, in-app purchase)

Gunman Clive Jeux casual iOS/Android Prototypes mobile
Points forts
Performances natives sur mobile, Lua simple à apprendre, export iOS + Android depuis un même code, gratuit depuis 2020.
Points faibles
Communauté plus petite depuis le passage open source, moins de ressources qu'avant, pas adapté au web.
Exemple minimal en Lua (Solar2D)
-- main.lua — afficher un rectangle à l'écran local rect = display.newRect( display.contentCenterX, -- x centré display.contentCenterY, -- y centré 100, 100 -- largeur, hauteur ) rect:setFillColor( 0.2, 0.8, 0.4 ) -- couleur RGB 0–1 -- Transition simple transition.to( rect, { time=1000, rotation=360 } )
📱
Lua est intentionnellement minimaliste. C'est le même langage qu'utilise Roblox pour ses scripts — si tu connais déjà Roblox Studio, tu as une longueur d'avance.

Section 5
🚀
Lien avec ce que tu connais

Tu as appris à créer des jeux avec le canvas HTML5 brut. Phaser.js automatise tout ce que tu faisais à la main :

Canvas brut (vu en cours)
Tu gères toi-même : boucle de jeu, sprites, physique, collisions, scènes, inputs, sons.
Phaser.js (framework)
La boucle tourne tout seul, les sprites s'animent, la physique est préconfigurée. Tu te concentres sur le gameplay.

Le canvas que tu maîtrises déjà, c'est la compréhension sous-jacente qui te permet d'utiliser Phaser intelligemment — tu sais ce qui se passe réellement derrière l'abstraction.

🔗
Phaser utilise le canvas HTML5 en interne — le même ctx.fillRect(), le même requestAnimationFrame(). Ce que tu as appris n'est pas jeté : c'est la fondation.
