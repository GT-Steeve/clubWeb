📝 CRUD & Formulaires

Créer, lire, modifier, supprimer du contenu à travers des formulaires Django.

Create Read Update Delete ModelForm
Le concept — CRUD
📦
Les 4 opérations fondamentales

Tous les sites qui gèrent du contenu — réseaux sociaux, blogs, e-commerces — reposent sur les mêmes 4 opérations. On les appelle le CRUD.

C Create Écrire un nouvel article
R Read Lire la liste ou le détail
U Update Modifier un article existant
D Delete Supprimer un article

Le R (Read) est déjà fait — c'est la vue liste_articles du cours précédent. Dans ce cours, on ajoute C, U et D grâce aux formulaires Django.

01 — forms.py — Le ModelForm
📋 blog/forms.py À créer manuellement

Un ModelForm génère automatiquement un formulaire HTML à partir d'un model Django. Plus besoin d'écrire chaque champ à la main — Django s'en charge.

blog/forms.py — CRÉER CE FICHIER 
from django import forms
from .models import Article

class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article          # on part du model Article
        fields = [               # champs à afficher dans le formulaire
            'titre',
            'contenu',
            'publie',
        ]
        # 'auteur' est exclu car on l'ajoute automatiquement (request.user)
        widgets = {
            'titre':   forms.TextInput(attrs={'placeholder': 'Titre de l\'article'}),
            'contenu': forms.Textarea(attrs={'rows': 8}),
        }
Pourquoi ModelForm plutôt qu'un form HTML classique ?
✅ Génère les champs automatiquement depuis le model
✅ Valide les données selon les types du model
✅ Sauvegarde directement en BDD avec form.save()
✅ Affiche les erreurs de validation automatiquement
💡 fields vs exclude — Listez toujours explicitement les champs avec fields. N'utilisez jamais fields = '__all__' : ça exposerait tous les champs, y compris des données sensibles.
02 — C — Créer un article
✏️ blog/views.py — creer_article POST = sauvegarder · GET = afficher le formulaire

Toute vue de création suit le même pattern : si la requête est GET → afficher un formulaire vide. Si POST → valider et sauvegarder.

blog/views.py 
from django.contrib.auth.decorators import login_required
from .forms import ArticleForm

@login_required
def creer_article(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            article = form.save(commit=False)  # objet sans sauvegarder
            article.auteur = request.user        # on ajoute l'auteur
            article.save()                     # sauvegarde en BDD
            return redirect('blog:detail', pk=article.pk)
    else:
        form = ArticleForm()                  # formulaire vide

    return render(request, 'blog/article_form.html', {
        'form': form,
        'titre_page': 'Nouvel article',
        'bouton': 'Publier',
    })
templates/blog/article_form.html 
{% extends "base.html" %}
{% block content %}

<h2>{{ titre_page }}</h2>

<form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">{{ bouton }}</button>
    <a href="{% url 'blog:liste' %}">Annuler</a>
</form>

{% endblock %}
♻️ Un seul template pour créer et modifier — On réutilise article_form.html pour la création et la modification. Seul le contexte change (titre_page et bouton).
03 — U — Modifier un article
✏️ blog/views.py — modifier_article Pré-remplir le formulaire avec les données existantes

La vue de modification est presque identique à la création. La différence : on charge l'article existant et on le passe au formulaire pour le pré-remplir.

blog/views.py 
from django.shortcuts import get_object_or_404

@login_required
def modifier_article(request, pk):
    article = get_object_or_404(Article, pk=pk)

    # Sécurité : seul l'auteur peut modifier son article
    if article.auteur != request.user:
        return redirect('blog:liste')

    if request.method == 'POST':
        form = ArticleForm(request.POST, instance=article) # instance = article à modifier
        if form.is_valid():
            form.save()
            return redirect('blog:detail', pk=article.pk)
    else:
        form = ArticleForm(instance=article) # pré-rempli avec les données de l'article

    return render(request, 'blog/article_form.html', {
        'form': form,
        'titre_page': 'Modifier l\'article',
        'bouton': 'Enregistrer',
    })
🔑 instance=article — Ce paramètre est la clé. Avec un GET, il pré-remplit le formulaire. Avec un POST, il met à jour l'article existant plutôt d'en créer un nouveau.
🛡️ Vérifiez toujours l'auteur ! Sans la vérification article.auteur != request.user, n'importe quel utilisateur connecté pourrait modifier les articles des autres en tapant l'URL directement.
04 — D — Supprimer un article
🗑️ blog/views.py — supprimer_article Toujours confirmer avant de supprimer

La suppression doit toujours passer par une confirmation. On n'utilise jamais un simple lien <a href> pour supprimer — ce serait dangereux (un robot peut suivre des liens).

blog/views.py 
@login_required
def supprimer_article(request, pk):
    article = get_object_or_404(Article, pk=pk)

    # Sécurité : seul l'auteur peut supprimer
    if article.auteur != request.user:
        return redirect('blog:liste')

    if request.method == 'POST':
        article.delete()                  # suppression réelle
        return redirect('blog:liste')

    # GET → page de confirmation
    return render(request, 'blog/confirmer_suppression.html', {'article': article})
templates/blog/confirmer_suppression.html 
{% extends "base.html" %}
{% block content %}

<h2>Supprimer cet article ?</h2>
<p>« {{ article.titre }} » sera définitivement supprimé.</p>

<form method="post">
    {% csrf_token %}
    <button type="submit">Confirmer la suppression</button>
    <a href="{% url 'blog:detail' article.pk %}">Annuler</a>
</form>

{% endblock %}
🍝 Effet spaghetti classique — Utiliser <a href="/supprimer/42"> au lieu d'un formulaire POST. Un outil de test automatique (ou un robot) peut suivre ce lien et vider votre base de données sans que personne ne clique dessus.
05 — Toutes les URLs CRUD
🗺️ blog/urls.py 4 routes pour 4 opérations
blog/urls.py 
from django.urls import path
from . import views

app_name = 'blog'

urlpatterns = [
    # READ — accessible à tous
    path('',                      views.liste_articles,    name='liste'),
    path('<int:pk>/',             views.detail_article,    name='detail'),

    # CREATE — @login_required dans la vue
    path('creer/',               views.creer_article,     name='creer'),

    # UPDATE — @login_required + vérif auteur dans la vue
    path('<int:pk>/modifier/',   views.modifier_article,  name='modifier'),

    # DELETE — @login_required + vérif auteur + confirmation
    path('<int:pk>/supprimer/',  views.supprimer_article, name='supprimer'),
]
Récapitulatif des URLs
/blog/ → liste (GET)
/blog/42/ → détail (GET)
/blog/creer/ → formulaire création (GET) / save (POST)
/blog/42/modifier/ → formulaire modif (GET) / save (POST)
/blog/42/supprimer/ → confirmation (GET) / suppression (POST)
06 — Messages de confirmation à l'utilisateur
💬 Django Messages Framework Informer l'utilisateur après une action

Après une création, modification ou suppression, il est important d'informer l'utilisateur que son action a réussi. Django inclut un système de messages flash pour ça.

blog/views.py — ajouter les messages 
from django.contrib import messages

@login_required
def creer_article(request):
    if request.method == 'POST':
        form = ArticleForm(request.POST)
        if form.is_valid():
            article = form.save(commit=False)
            article.auteur = request.user
            article.save()
            messages.success(request, 'Article publié avec succès !')
            return redirect('blog:detail', pk=article.pk)
    # ...

@login_required
def supprimer_article(request, pk):
    # ...
    if request.method == 'POST':
        article.delete()
        messages.success(request, 'Article supprimé.')
        return redirect('blog:liste')
templates/base.html — afficher les messages 
{% if messages %}
  {% for message in messages %}
    <div class="message {{ message.tags }}">
      {{ message }}
    </div>
  {% endfor %}
{% endif %}
07 — Tableau de bord créateur
🎛️ Tableau de bord — vue d'ensemble Lier tout ensemble

Un tableau de bord centralise les actions du créateur : voir ses articles, en créer, modifier ou supprimer. Voici comment le template fait le lien entre toutes les vues CRUD.

templates/blog/dashboard.html 
{% extends "base.html" %}
{% block content %}

<h2>Mes articles</h2>
<a href="{% url 'blog:creer' %}">+ Nouvel article</a>

{% for article in articles %}
  <div>
    <h3>{{ article.titre }}</h3>

    <!-- Modifier → URL Update -->
    <a href="{% url 'blog:modifier' article.pk %}">Modifier</a>

    <!-- Supprimer → formulaire POST vers URL Delete -->
    <form method="post" action="{% url 'blog:supprimer' article.pk %}">
        {% csrf_token %}
        <button type="submit">Supprimer</button>
    </form>

  </div>
{% empty %}
  <p>Vous n'avez pas encore écrit d'article.</p>
{% endfor %}

{% endblock %}
⚠️ Le bouton Supprimer doit être dans un <form method="post"> — Jamais dans un simple lien. La suppression doit toujours être une requête POST, pas GET.

✅ Les 3 règles d'or du CRUD Django — (1) Toujours @login_required sur C, U, D. (2) Toujours vérifier que article.auteur == request.user avant U et D. (3) Toujours un formulaire POST pour supprimer — jamais un lien GET.
