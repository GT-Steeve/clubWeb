Concepts clés du vibecoding HTML/CSS/JS
Les 3 couches du frontend↻
HTML = structure & contenu
CSS = apparence & style
JS = comportement & logique
Liaison HTML → CSS↻
Les class et id dans le HTML doivent correspondre exactement aux sélecteurs dans le CSS.
Liaison JS → HTML↻
Les id utilisés dans getElementById() doivent exister dans le HTML.
Liaison CSS ↔ JS↻
Les classes que JS ajoute via classList.toggle() doivent être définies dans le CSS pour avoir un effet visuel.
Où placer le script JS ?↻
En bas du <body>, juste avant </body> — pour que le HTML soit chargé avant que le JS essaie de l'atteindre.
Qu'est-ce que object-fit: cover ?↻
Remplit le conteneur avec l'image sans déformer — recadre automatiquement si nécessaire. Indispensable pour les galeries.
Outil de débogage frontend↻
F12 — ouvre les DevTools. Onglet Elements pour le HTML/CSS, Console pour les erreurs JS, Network pour les requêtes.
Approche mobile-first↻
On écrit le CSS de base pour mobile, puis on ajoute des @media (min-width: ...) pour les écrans plus grands.
Que fait classList.toggle('active') ?↻
Ajoute la classe active si elle n'est pas là, la supprime si elle est déjà là — idéal pour les menus et les accordéons.
Prompt CSS visuel — la règle↻
Décrire ce qu'on voit plutôt que le code : « fond blanc, coins arrondis, ombre légère » plutôt que « background white ».

04 — Scénarios — que faites-vous ?
Scénario 1 — CSS
🎨 L'IA génère un CSS avec .card:hover { transform: translateY(-4px); }. Tu testes dans le navigateur : aucun effet au survol. Que vérifies-tu en premier ?
Que la carte a bien une hauteur définie en CSS
Que la classe dans le HTML est bien class="card" et non class="carte" ou un autre nom différent
Que le fichier CSS est enregistré en UTF-8
✓ Un effet hover qui ne fonctionne pas est presque toujours un problème de nom de sélecteur. Le CSS cible .card mais l'élément HTML a peut-être une classe différente. Vérifier dans F12 → Elements → Styles si la règle est bien présente et non barrée.
Scénario 2 — JS
⚡ Tu intègres du JS généré par l'IA. La console F12 affiche : TypeError: Cannot read properties of null (reading 'addEventListener') sur la ligne document.getElementById('btn-toggle').addEventListener(...). Quelle est la cause la plus probable ?
Le navigateur ne supporte pas addEventListener
Le script est dans le <head> et s'exécute avant que le HTML soit chargé, ou l'élément avec id="btn-toggle" n'existe pas dans le HTML
Il manque un point-virgule dans le JS
✓ Cannot read properties of null signifie que getElementById() a retourné null — l'élément n'a pas été trouvé. Soit le script s'exécute avant que le HTML soit chargé (placer le script en bas du body), soit l'id dans le JS ne correspond pas à celui du HTML.
Scénario 3 — Assemblage
🧩 L'IA génère un menu mobile. Le CSS contient .menu.open { display: flex; } et le JS fait menu.classList.toggle('active'). Tu testes : le menu ne s'ouvre pas. Que se passe-t-il ?
Le CSS est mal écrit — display: flex ne peut pas fonctionner ici
Le JS toggle la classe active mais le CSS écoute la classe open — les deux noms ne correspondent pas
Il manque un {% load static %} dans le template
✓ C'est la liaison CSS ↔ JS cassée : le JS ajoute .active mais le CSS attend .open. Rien ne se passe visuellement même si le JS fonctionne. Solution : harmoniser les noms — soit changer le JS en toggle('open'), soit changer le CSS en .menu.active.
Scénario 4 — Responsive
📱 Tu demandes à l'IA de rendre une grille responsive. Elle génère du CSS Grid. Sur mobile, les cartes sont trop larges et débordent de l'écran. Quelle est l'erreur la plus courante dans ce cas ?
Les cartes ont une police trop grande
Les cartes ont une largeur fixe en pixels (width: 300px) au lieu d'utiliser 100% ou 1fr, et la meta viewport est peut-être absente dans le HTML
Le navigateur mobile ne supporte pas CSS Grid
✓ Le débordement sur mobile vient presque toujours d'une largeur fixe en pixels. En responsive, utiliser des unités relatives (%, fr, vw) ou max-width. Vérifier aussi que la balise <meta name="viewport" ...> est bien dans le <head>.
