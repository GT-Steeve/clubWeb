📁 Structure d'un projet Django

Suite de django-start — on crée l'app blog, on explore ce qui est généré automatiquement et on crée le reste à la main.

Suite de django-start Projet guidé 7 étapes ~25 min startapp blog
🎯
Objectif du projet

Tu repars du projet Django vierge créé dans django-start. Tu vas lancer python manage.py startapp blog, observer ce que Django génère automatiquement, puis créer manuellement les fichiers manquants et configurer le projet pour que tout soit relié.

💡Règle du cours — Django génère les fichiers de base, mais plusieurs éléments indispensables doivent être créés à la main : urls.py dans l'app, les dossiers templates/ et static/. C'est toi qui construis la structure complète.
🗺️

Progression 0 / 7 étapes
1
Lancer startapp blog
Une commande qui génère tout le squelette de l'app.
✓

Depuis le dossier racine du projet (là où se trouve manage.py), lance cette commande avec l'environnement virtuel actif :

Terminal — avec (env) actif 
python manage.py startapp blog

Django crée immédiatement un dossier blog/ avec ces fichiers à l'intérieur :

✅
models.py
Vide pour l'instant — tu y écriras tes tables plus tard.
✅
views.py
Vide — les fonctions qui répondent aux requêtes HTTP.
✅
admin.py
Pour exposer les données dans l'interface /admin/.
✅
apps.py
Configuration de l'app — rarement modifié.
✅
tests.py
Pour écrire des tests automatisés.
✅
migrations/
Dossier créé avec un __init__.py vide — Django le gère.
⚠️ Ce que Django ne crée pas — urls.py, templates/ et static/ sont absents. C'est volontaire : tu les crées toi-même selon les besoins de ton projet.
2
Déclarer l'app dans settings.py
Sans ça, Django ignore complètement l'app blog.
✓

Ouvre monprojet/settings.py et trouve la liste INSTALLED_APPS. Ajoute 'blog' à la fin :

monprojet/settings.py — à modifier 
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'blog',  # ← ajoute cette ligne
]
🚨 Effet spaghetti classique — Oublier cette ligne est l'erreur n°1. Les migrations ne trouvent pas tes models, les templates ne sont pas détectés, tout semble planter sans explication. Commence toujours par déclarer l'app.
3
Créer blog/urls.py manuellement
Le fichier que Django oublie de générer — à toi de le créer.
✓

Dans le dossier blog/, crée un nouveau fichier vide nommé urls.py. Copie-y ce contenu de base :

blog/urls.py — à créer manuellement 
from django.urls import path
from . import views

app_name = 'blog'

urlpatterns = [
    # Les routes de l'app blog seront ajoutées ici
]
📌 app_name = 'blog' permet d'utiliser les URL nommées dans les templates avec le préfixe : {% url 'blog:liste' %}. C'est une bonne pratique à adopter dès le début.
4
Relier dans monprojet/urls.py
Le routeur principal doit connaître l'existence de l'app.
✓

Ouvre monprojet/urls.py et ajoute l'include() vers l'app blog :

monprojet/urls.py — à modifier 
from django.contrib import admin
from django.urls import path, include  # ← ajoute include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('blog/', include('blog.urls')),  # ← ajoute cette ligne
]
💡 La règle d'or — monprojet/urls.py ne contient que des include(). Les vraies routes (vers les views) sont dans blog/urls.py. Le projet délègue, l'app gère.
🚨 Piège classique — Si tu oublies cette ligne, toutes les URLs de l'app retournent une erreur 404. Django ne sait pas où chercher les routes de blog/.
5
Créer le dossier templates/
Avec le sous-dossier obligatoire au nom de l'app.
✓

Crée cette arborescence de dossiers à l'intérieur de blog/, puis un fichier HTML vide dedans :

Structure à créer 
blog/
└── templates/
    └── blog/           # sous-dossier obligatoire = nom de l'app
        └── base.html   # ton premier template

Contenu minimal pour base.html :

blog/templates/blog/base.html 
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>{% block title %}Mon Blog{% endblock %}</title>
</head>
<body>
    {% block content %}{% endblock %}
</body>
</html>
🔑 Le sous-dossier blog/ est obligatoire. Sans lui, Django peut confondre des templates de même nom entre différentes apps. Toujours : templates/<nom_app>/fichier.html.
6
Créer le dossier static/
CSS, JS et images — la même convention de sous-dossier.
✓

Crée cette arborescence dans blog/ :

Structure à créer 
blog/
└── static/
    └── blog/           # sous-dossier obligatoire = nom de l'app
        └── css/
            └── style.css

Pour charger ce CSS dans un template, utilise la balise {% load static %} :

Dans un template HTML 
{% load static %}
<link rel="stylesheet" href="{% static 'blog/css/style.css' %}">
⚠️ Sans {% load static %} en haut du template, la balise {% static %} provoque une erreur. Cette ligne doit toujours être présente avant la première utilisation.
7
Vérifier que tout est en place
Relancer le serveur et confirmer l'absence d'erreurs.
✓

Lance le serveur et lis attentivement le retour du terminal :

Terminal — avec (env) actif 
python manage.py runserver

Le terminal doit afficher aucune erreur de module ou d'import. Les warnings de migrations sont normaux.

models.py, views.py, admin.py, apps.py, tests.py, migrations/
Générés par startapp — tu ne les as pas créés.
🔴
blog/urls.py, templates/blog/, static/blog/
Créés manuellement par toi — Django ne les génère pas.
✏️
settings.py, monprojet/urls.py
Modifiés par toi — INSTALLED_APPS et include().
🎉 Structure complète. Ton projet Django est maintenant correctement architecturé. Tu peux commencer à écrire des models dans models.py, des views dans views.py, et des templates dans templates/blog/.
