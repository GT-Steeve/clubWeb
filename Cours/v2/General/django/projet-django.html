🗄️ Projet — ORM & Admin Django

Suite du projet blog : on remplace les données codées en dur par une vraie base de données.

models.py migrations admin.py ORM queries superuser
Suite de : projet-django-templates.html — tu as un blog avec templates, héritage et DTL.
Objectif : Créer le Model Article, appliquer les migrations et connecter la base de données à tes vues.
Progression 0 / 6 étapes
1
Créer le Model Article
▾

Dans blog/models.py, définis la classe Article qui hérite de models.Model. Chaque attribut de la classe devient une colonne en base de données.

blog/models.py
from django.db import models from django.contrib.auth.models import User class Article(models.Model): titre = models.CharField(max_length=200) contenu = models.TextField() auteur = models.ForeignKey(User, on_delete=models.CASCADE) date_creation = models.DateTimeField(auto_now_add=True) publie = models.BooleanField(default=True) class Meta: ordering = ['-date_creation'] def __str__(self): return self.titre
ℹ️
ForeignKey crée une relation N:1 — un utilisateur peut avoir plusieurs articles. on_delete=models.CASCADE supprime les articles si l'utilisateur est supprimé.
2
Appliquer les migrations
▾

Django doit transformer ton Model Python en table SQL. Deux commandes sont nécessaires :

Terminal
$ python manage.py makemigrations Migrations for 'blog': blog/migrations/0001_initial.py - Create model Article $ python manage.py migrate Operations to perform: Apply all migrations: admin, auth, blog, contenttypes, sessions Running migrations: Applying blog.0001_initial... OK
⚠️
makemigrations génère le fichier de migration (comme un "plan"). migrate l'applique à la base de données. Ne jamais oublier les deux.
💡
Si tu modifies un Model existant (ajouter un champ, changer un type), relance toujours makemigrations puis migrate.
3
Enregistrer dans l'Admin Django
▾

Django génère automatiquement une interface d'administration pour gérer tes données. Il suffit d'enregistrer ton Model dans blog/admin.py.

blog/admin.py
from django.contrib import admin from .models import Article @admin.register(Article) class ArticleAdmin(admin.ModelAdmin): list_display = ['titre', 'auteur', 'date_creation', 'publie'] list_filter = ['publie', 'auteur'] search_fields = ['titre', 'contenu']
✨
list_display choisit les colonnes visibles dans la liste admin. list_filter ajoute des filtres latéraux. search_fields active la barre de recherche.
4
Créer un superutilisateur
▾

Pour accéder à l'interface d'administration, tu as besoin d'un compte administrateur. Django fournit une commande dédiée :

Terminal
$ python manage.py createsuperuser Username: admin Email address: admin@blog.com Password: ******** Password (again): ******** Superuser created successfully.

Lance ensuite le serveur et visite http://127.0.0.1:8000/admin/. Connecte-toi, puis crée quelques articles depuis l'interface graphique.

$ python manage.py runserver
🔗
Rends-toi sur http://127.0.0.1:8000/admin/ → clique sur "Articles" → "Ajouter un article" → remplis le formulaire et sauvegarde. Tu verras les données apparaître dans la BDD.
5
Connecter la BDD à la vue index
▾

Remplace le dictionnaire Python codé en dur par une vraie requête ORM. La vue récupère les articles publiés depuis la base de données.

blog/views.py — avant vs après
# AVANT — données codées en dur def index(request): contexte = { 'articles': [ {'titre': 'Mon premier article', 'auteur': 'Alice'}, ] } return render(request, 'blog/index.html', contexte) # APRÈS — requête ORM from .models import Article def index(request): articles = Article.objects.filter(publie=True) return render(request, 'blog/index.html', {'articles': articles})
💡
Article.objects.filter(publie=True) retourne un QuerySet — tous les articles dont le champ publie vaut True. L'ORM traduit ça en SQL automatiquement.
Ajouter aussi la vue détail
from django.shortcuts import render, get_object_or_404 def detail(request, pk): article = get_object_or_404(Article, pk=pk, publie=True) return render(request, 'blog/detail.html', {'article': article})
6
Mettre à jour les templates & URLs
▾

Les objets Article retournés par l'ORM ont des attributs Python — adapte tes templates pour accéder aux vrais champs du model.

templates/blog/index.html — boucle mise à jour
{% for article in articles %} <article class="article-card"> <h2><a href="{% url 'blog:detail' article.pk %}">{{ article.titre }}</a></h2> <p class="meta"> par {{ article.auteur.username }} — {{ article.date_creation|date:"d F Y" }} </p> <p>{{ article.contenu|truncatewords:30 }}</p> </article> {% empty %} <p>Aucun article publié pour l'instant.</p> {% endfor %}
blog/urls.py — ajouter l'URL de détail
from django.urls import path from . import views app_name = 'blog' urlpatterns = [ path('', views.index, name='index'), path('article/<int:pk>/', views.detail, name='detail'), ]
⚠️
Le filtre |date:"d F Y" formate une date Python en français. |truncatewords:30 coupe le texte après 30 mots — pratique pour les aperçus.
✅
Visite http://127.0.0.1:8000/blog/ — tu dois voir les articles créés dans l'admin. Clique sur un titre pour voir la page de détail.

Le blog lit maintenant de vraies données depuis la base de données ✓
