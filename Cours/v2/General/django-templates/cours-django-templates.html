Le rôle du système de templates

Un template Django est un fichier HTML enrichi avec le Django Template Language (DTL). Il sert à séparer le code Python de la présentation HTML : la vue prépare les données, le template les affiche.

Données

contexte { }

template.html
Rendu

Réponse HTTP
HTML final

Le DTL offre deux types de balises : {{ variable }} pour afficher des données, et {% tag %} pour la logique (boucles, conditions, héritage).

💡 DTL ≠ Python — Le Django Template Language est volontairement simplifié. On ne peut pas exécuter du code Python arbitraire dans un template. C'est un choix de conception : les templates restent lisibles par des non-développeurs.
00 — Structure des dossiers templates
📁 Arborescence du projet Où placer vos templates

Django cherche les templates dans un dossier templates/ à l'intérieur de chaque app déclarée dans INSTALLED_APPS. La convention est d'ajouter un sous-dossier au nom de l'app pour éviter les conflits de noms.

Structure recommandée 
monsite/
├── monsite/
│   ├── settings.py
│   └── urls.py
├── blog/
│   ├── models.py
│   ├── views.py
│   ├── urls.py
│   └── templates/            # ← dossier templates de l'app
│       └── blog/             # ← sous-dossier au nom de l'app
│           ├── base.html     # template parent (layout)
│           ├── article_list.html
│           └── article_detail.html
└── static/                   # CSS, JS, images (globaux)
    ├── css/
    │   └── style.css
    └── js/
        └── main.js
🚨 Erreur classique — Placer le template directement dans blog/templates/article_list.html sans le sous-dossier blog/. Django peut confondre des templates d'apps différentes qui ont le même nom. Respectez toujours la convention templates/<nom_app>/<fichier>.html.

Deux approches possibles

ApprocheCheminQuand l'utiliser
Par app ✅blog/templates/blog/Petits projets, templates spécifiques à l'app
Dossier globaltemplates/ à la racineTemplates partagés (base, 404, 500…)
🗂️ Bonne pratique — Combinez les deux : un dossier templates/ global à la racine pour le base.html et les pages d'erreur, et un dossier templates/<app>/ par app pour ses propres templates.
01 — Configurer les templates dans settings.py
⚙️ monsite/settings.py Déclarer où Django cherche les templates

La configuration des templates se fait dans la variable TEMPLATES de settings.py. Par défaut, Django utilise le moteur DTL et cherche les templates dans chaque app. Vous pouvez aussi ajouter un dossier global.

monsite/settings.py 
import os

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',

        # Dossier(s) global(aux) à la racine du projet
        'DIRS': [os.path.join(BASE_DIR, 'templates')],

        # Chercher aussi dans templates/ de chaque app
        'APP_DIRS': True,

        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]
Ce que ça configure
DIRS — Liste les dossiers globaux où chercher en premier
APP_DIRS: True — Active la recherche dans chaque app/templates/
context_processors — Variables automatiquement disponibles dans tous les templates (user, request, messages…)
02 — Créer le template parent base.html
🏗️ templates/base.html Le layout partagé de tout le site

Le template de base (ou layout) définit la structure HTML commune à toutes les pages : l'en-tête, le pied de page, les imports CSS/JS. Les templates enfants héritent de ce layout et ne surchargent que des blocs spécifiques.

templates/base.html 
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">

    <!-- Titre dynamique avec valeur par défaut -->
    <title>{% block titre %}Mon Blog{% endblock %}</title>

    <!-- ① Charger les fichiers statiques -->
    {% load static %}

    <!-- ② Lier le CSS depuis le dossier static/ -->
    <link rel="stylesheet" href="{% static 'css/style.css' %}">

    <!-- Bloc CSS supplémentaire pour les pages enfants -->
    {% block extra_css %}{% endblock %}
</head>

<body>

    <!-- Barre de navigation commune -->
    <nav>
        <a href="{% url 'blog:liste' %}">🏠 Accueil</a>
    </nav>

    <!-- ③ Afficher les messages flash (succès, erreurs…) -->
    {% if messages %}
      <ul class="messages">
        {% for message in messages %}
          <li class="{{ message.tags }}">{{ message }}</li>
        {% endfor %}
      </ul>
    {% endif %}

    <!-- ④ Bloc principal — chaque page enfant remplit ce bloc -->
    <main>
        {% block contenu %}{% endblock %}
    </main>

    <footer>
        <p>Mon Blog — {% now "Y" %}</p>
    </footer>

    <!-- ⑤ JS en bas de page -->
    <script src="{% static 'js/main.js' %}"></script>

    <!-- Bloc JS supplémentaire pour les pages enfants -->
    {% block extra_js %}{% endblock %}

</body>
</html>
🧩 Les blocs ({% block %}) sont des espaces réservés — Chaque bloc nommé peut être remplacé ou complété par un template enfant. Si un enfant ne redéfinit pas le bloc, le contenu par défaut du parent s'affiche.
03 — Héritage de templates avec extends
🎨 blog/templates/blog/article_list.html Template enfant — hérite du parent

{% extends %} doit toujours être la toute première ligne du fichier. Le template enfant n'écrit que ce qui est différent du parent, à l'intérieur des blocs.

blog/templates/blog/article_list.html 
<!-- ① Hériter du template parent -->
{% extends "base.html" %}

<!-- ② Charger des tags supplémentaires si besoin -->
{% load static %}

<!-- ③ Surcharger le titre de la page -->
{% block titre %}{{ titre_page }} — Mon Blog{% endblock %}

<!-- ④ Remplir le bloc principal -->
{% block contenu %}

<h1>{{ titre_page }}</h1>

<!-- Boucle sur la liste d'articles -->
{% for article in articles %}
  <article>
    <h2>
      <a href="{% url 'blog:detail' article.pk %}">{{ article.titre }}</a>
    </h2>
    <p>Par {{ article.auteur }} — {{ article.publie_le|date:"d/m/Y" }}</p>
    <p>{{ article.contenu|truncatewords:30 }}</p>
  </article>
{% empty %}
  <p>Aucun article publié pour le moment.</p>
{% endfor %}

{% endblock %}
Ce que produit ce template
Le template enfant n'écrit que le contenu de la page.
Django fusionne automatiquement parent + enfant.
Le <nav>, le <footer>, et les imports CSS/JS viennent du base.html.
04 — Le Django Template Language (DTL)
{ }
Variables — afficher des données

Les doubles accolades {{ }} affichent la valeur d'une variable du contexte envoyé par la vue. Django gère automatiquement l'échappement HTML pour prévenir les failles XSS.

Syntaxe des variables 
<!-- Variable simple -->
{{ titre_page }}

<!-- Accès à une propriété d'objet -->
{{ article.titre }}
{{ article.auteur.username }}

<!-- Accès à un élément de liste -->
{{ articles.0 }}          <!-- premier élément -->

<!-- Variable avec valeur par défaut -->
{{ user.nom|default:"Visiteur" }}

<!-- Afficher du HTML brut (⚠️ uniquement pour contenu sûr) -->
{{ article.contenu|safe }}
%
Tags — logique et structure

Les balises de template {% %} permettent les conditions, les boucles, l'héritage, les liens, et bien plus. Elles contiennent de la logique, pas des valeurs.

TagRôleExemple
{% if %} … {% endif %}Condition{% if user.is_authenticated %}
{% for %} … {% endfor %}Boucle{% for art in articles %}
{% extends "" %}Héritage parent{% extends "base.html" %}
{% block %} … {% endblock %}Zone à surcharger{% block contenu %}{% endblock %}
{% include "" %}Inclure un sous-template{% include "blog/carte.html" %}
{% url "" %}Générer une URL{% url 'blog:detail' pk %}
{% static "" %}Lier un fichier statique{% static 'css/style.css' %}
{% load %}Charger un jeu de tags{% load static %}
{% comment %}Commentaire ignoré{% comment %} notes {% endcomment %}
{% csrf_token %}Sécuriser un formulaireDans toute balise <form>
|
Filtres — transformer les valeurs

Les filtres s'appliquent avec le pipe | et transforment une variable avant de l'afficher. On peut en chaîner plusieurs.

Filtres essentiels 
<!-- Tronquer à N mots -->
{{ article.contenu|truncatewords:30 }}

<!-- Formater une date -->
{{ article.publie_le|date:"d/m/Y" }}
{{ article.publie_le|date:"D d M Y" }}  <!-- Jeu 01 Jan 2025 -->

<!-- Mettre en majuscules / minuscules -->
{{ article.titre|upper }}
{{ article.titre|lower }}
{{ article.titre|title }}

<!-- Compter les caractères / mots -->
{{ article.contenu|length }}
{{ article.contenu|wordcount }}

<!-- Valeur par défaut si vide -->
{{ article.image|default:"placeholder.jpg" }}

<!-- Remplacer les sauts de ligne par des <br> -->
{{ article.contenu|linebreaksbr }}

<!-- Chaîner des filtres -->
{{ article.titre|lower|title }}
05 — Conditions et boucles avancées
if
Conditions dans les templates
Exemples de conditions DTL 
<!-- Condition simple -->
{% if article.publie %}
  <span class="badge-vert">Publié</span>
{% else %}
  <span class="badge-gris">Brouillon</span>
{% endif %}

<!-- elif : plusieurs branches -->
{% if articles|length == 0 %}
  <p>Aucun article.</p>
{% elif articles|length == 1 %}
  <p>Un seul article.</p>
{% else %}
  <p>{{ articles|length }} articles.</p>
{% endif %}

<!-- Opérateurs : and, or, not, ==, !=, <, >, in -->
{% if user.is_authenticated and user.is_staff %}
  <a href="/admin/">Admin</a>
{% endif %}
for
Boucles et variables de boucle
Variables automatiques dans {% for %} 
{% for article in articles %}
  <article class="{% if forloop.first %}premier{% endif %}">

    <!-- forloop.counter : numéro 1, 2, 3… -->
    <span>{{ forloop.counter }}</span>

    <!-- forloop.counter0 : numéro 0, 1, 2… -->
    <!-- forloop.first : True pour le 1er élément -->
    <!-- forloop.last  : True pour le dernier -->
    <!-- forloop.revcounter : compte à rebours -->

    <h2>{{ article.titre }}</h2>
  </article>

{% empty %}
  <!-- Affiché si la liste est vide -->
  <p>Aucun résultat.</p>
{% endfor %}
✨ {% empty %} — Toujours ajouter un bloc {% empty %} dans vos boucles. Il s'affiche si la liste est vide et évite une page blanche silencieuse.
06 — Inclusion de sous-templates
🧩 {% include %} Réutiliser des morceaux de HTML

{% include %} insère le contenu d'un autre template. Pratique pour les composants réutilisables : carte d'article, menu, pagination…

blog/templates/blog/article_list.html 
{% for article in articles %}
  <!-- Inclure un composant carte pour chaque article -->
  {% include "blog/composants/carte_article.html" with article=article %}
{% endfor %}
blog/templates/blog/composants/carte_article.html 
<article class="carte">
  <h2>
    <a href="{% url 'blog:detail' article.pk %}">{{ article.titre }}</a>
  </h2>
  <p>{{ article.contenu|truncatewords:20 }}</p>
</article>
🔑 with variable=valeur — Le mot-clé with passe des variables au sous-template. Sans with, le sous-template hérite de tout le contexte de la page parente.
07 — Inclure CSS, JS et images (fichiers statiques)
🎨 static/ — CSS, JS, images Lier vos ressources frontend

Les fichiers statiques (CSS, JS, images) sont gérés par django.contrib.staticfiles. On les référence dans les templates avec {% static %} — jamais avec un chemin en dur.

1. Configurer settings.py

monsite/settings.py 
# Déjà dans INSTALLED_APPS :
'django.contrib.staticfiles',

# URL publique des fichiers statiques
STATIC_URL = 'static/'

# Dossier(s) supplémentaires à la racine (optionnel)
STATICFILES_DIRS = [
    BASE_DIR / 'static',
]

# Dossier de collecte pour la prod (manage.py collectstatic)
STATIC_ROOT = BASE_DIR / 'staticfiles'

2. Utiliser {% static %} dans les templates

templates/base.html 
<!-- TOUJOURS charger le tag en premier -->
{% load static %}

<!-- CSS -->
<link rel="stylesheet" href="{% static 'css/style.css' %}">

<!-- JavaScript -->
<script src="{% static 'js/main.js' %}"></script>

<!-- Image -->
<img src="{% static 'images/logo.png' %}" alt="Logo">

<!-- Stocker l'URL dans une variable -->
{% static 'images/default.jpg' as img_defaut %}
<img src="{{ img_defaut }}" alt="Image par défaut">
🚨 N'oubliez jamais {% load static %} — Sans cette ligne, Django ne reconnaît pas le tag {% static %} et vous obtenez une erreur TemplateSyntaxError: Invalid block tag 'static'. C'est l'erreur n°1 avec les fichiers statiques.

3. Lancer le serveur de développement

python manage.py runserver
# En dev, Django sert automatiquement les fichiers statiques
# Django recherche dans static/ de chaque app ET dans STATICFILES_DIRS
🏭 En production — Django ne sert pas les fichiers statiques lui-même. Lancez python manage.py collectstatic pour rassembler tous les fichiers dans STATIC_ROOT, puis configurez Nginx ou Apache pour les servir.
08 — Générer des URLs avec {% url %}
🔗 {% url %} — liens dynamiques Ne jamais coder les URLs en dur

Le tag {% url %} génère une URL à partir du nom de la vue défini dans urls.py. Si vous changez le chemin, tous les liens se mettent à jour automatiquement.

Syntaxe du tag {% url %} 
<!-- URL sans paramètre -->
<a href="{% url 'blog:liste' %}">Tous les articles</a>

<!-- URL avec paramètre entier (pk) -->
<a href="{% url 'blog:detail' article.pk %}">Lire l'article</a>

<!-- URL avec paramètre slug -->
<a href="{% url 'blog:detail' article.slug %}">{{ article.titre }}</a>

<!-- Stocker l'URL dans une variable -->
{% url 'blog:detail' article.pk as url_detail %}
<a href="{{ url_detail }}">Détail</a>

<!-- URL vers l'admin -->
<a href="{% url 'admin:index' %}">Administration</a>
Rappel — le namespace dans urls.py
Le préfixe blog: vient de app_name = 'blog' dans blog/urls.py.
Sans namespace : {% url 'liste' %}
Avec namespace : {% url 'blog:liste' %} ← recommandé
09 — Relier la vue au template
⚡ blog/views.py Envoyer le contexte au template

La vue Python utilise render() pour associer un template à un dictionnaire de données appelé contexte. Les clés du dictionnaire deviennent des variables accessibles dans le template.

blog/views.py 
from django.shortcuts import render, get_object_or_404
from .models import Article

def liste_articles(request):
    articles = Article.objects.filter(publie=True).order_by('-publie_le')

    # Le contexte = dictionnaire clé:valeur
    # Les clés sont les noms de variables dans le template
    contexte = {
        'articles': articles,       # → {{ articles }} dans le template
        'titre_page': 'Mon Blog',   # → {{ titre_page }}
        'nb_articles': articles.count(),
    }

    # render(requête, chemin_template, contexte)
    return render(request, 'blog/article_list.html', contexte)


def detail_article(request, pk):
    article = get_object_or_404(Article, pk=pk, publie=True)

    return render(request, 'blog/article_detail.html', {
        'article': article,
    })
Correspondance vue ↔ template
Clé Python 'articles' → variable DTL {{ articles }}
Clé Python 'titre_page' → variable DTL {{ titre_page }}
Chemin 'blog/article_list.html' → fichier blog/templates/blog/article_list.html
