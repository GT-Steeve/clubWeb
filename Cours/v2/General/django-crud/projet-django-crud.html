📝 Djanjo — CRUD

Suite du projet blog : créer, modifier et supprimer des articles avec des formulaires.

ModelForm Create Update Delete Sécurité
Suite de : projet-django.html — tu as un blog avec un Model Article et une vraie BDD.
Objectif : Permettre aux utilisateurs de créer, modifier et supprimer leurs articles via des formulaires Django.
Progression 0 / 7 étapes
1
Créer blog/forms.py
▾

Django ne crée pas forms.py automatiquement — c'est un fichier à créer manuellement dans le dossier blog/. Le ModelForm génère un formulaire HTML directement depuis le Model.

blog/forms.py (nouveau fichier)
from django import forms from .models import Article class ArticleForm(forms.ModelForm): class Meta: model = Article fields = ['titre', 'contenu', 'publie'] # Ne jamais utiliser '__all__' — expose des champs sensibles
⚠️ SécuritéNe jamais écrire fields = '__all__'. Cela exposerait le champ auteur au formulaire — un utilisateur malveillant pourrait se l'attribuer. Listez toujours les champs explicitement.
2
Vue Create — creer_article
▾

La vue de création distingue deux cas : GET (afficher le formulaire vide) et POST (traiter les données soumises).

blog/views.py — ajouter
from django.shortcuts import render, redirect, get_object_or_404 from django.contrib.auth.decorators import login_required from .forms import ArticleForm @login_required def creer_article(request): if request.method == 'POST': form = ArticleForm(request.POST) if form.is_valid(): article = form.save(commit=False) article.auteur = request.user # on assigne l'auteur manuellement article.save() return redirect('blog:detail', pk=article.pk) else: form = ArticleForm() return render(request, 'blog/article_form.html', {'form': form})
💡
save(commit=False) crée l'objet Python sans l'écrire en BDD — ça permet d'ajouter auteur avant l'enregistrement final.
3
Template article_form.html
▾

Un seul template sert à la fois pour Create et Update — la vue passe les données du formulaire, Django s'occupe du rendu.

templates/blog/article_form.html
{% extends 'blog/base.html' %} {% block title %} {% if form.instance.pk %}Modifier{% else %}Créer{% endif %} un article {% endblock %} {% block content %} <h1> {% if form.instance.pk %}✏️ Modifier{% else %}✍️ Écrire{% endif %} un article </h1> <form method="post"> {% csrf_token %} {{ form.as_p }} <button type="submit"> {% if form.instance.pk %}Enregistrer les modifications{% else %}Publier{% endif %} </button> </form> {% endblock %}
⚠️
{% csrf_token %} est obligatoire dans tout formulaire POST. Il protège contre les attaques CSRF (Cross-Site Request Forgery). Django refusera le formulaire sans lui.
4
Vue Update — modifier_article
▾

La vue de modification est identique à Create, sauf qu'elle passe instance=article pour pré-remplir le formulaire et identifier l'objet à mettre à jour.

blog/views.py — ajouter
@login_required def modifier_article(request, pk): article = get_object_or_404(Article, pk=pk) if article.auteur != request.user: return redirect('blog:liste') if request.method == 'POST': form = ArticleForm(request.POST, instance=article) if form.is_valid(): form.save() return redirect('blog:detail', pk=article.pk) else: form = ArticleForm(instance=article) return render(request, 'blog/article_form.html', {'form': form})
⚠️ Sécurité — vérification de propriété@login_required vérifie qu'on est connecté, mais pas qu'on est le bon utilisateur. Sans article.auteur != request.user, n'importe quel utilisateur connecté peut modifier les articles des autres en tapant l'URL directement.
5
Vue Delete — supprimer_article
▾

La suppression nécessite une confirmation — on affiche une page intermédiaire avec un formulaire POST. Jamais via un simple lien GET.

blog/views.py — ajouter
from django.contrib import messages @login_required def supprimer_article(request, pk): article = get_object_or_404(Article, pk=pk) if article.auteur != request.user: return redirect('blog:liste') if request.method == 'POST': article.delete() messages.success(request, 'Article supprimé.') return redirect('blog:index') return render(request, 'blog/confirmer_suppression.html', {'article': article})
templates/blog/confirmer_suppression.html
{% extends 'blog/base.html' %} {% block content %} <h1>🗑️ Supprimer cet article ?</h1> <p><strong>{{ article.titre }}</strong></p> <p>Cette action est irréversible.</p> <form method="post"> {% csrf_token %} <button type="submit">Oui, supprimer</button> <a href="{% url 'blog:detail' article.pk %}">Annuler</a> </form> {% endblock %}
🚫
Ne jamais supprimer via un lien <a href> — un robot d'indexation pourrait suivre le lien et supprimer tes données. La suppression passe toujours par un formulaire POST.
6
Ajouter les URLs CRUD
▾

Connecte les trois nouvelles vues dans blog/urls.py. Les URLs avec <int:pk> capturent l'identifiant de l'article.

blog/urls.py — version complète
from django.urls import path from . import views app_name = 'blog' urlpatterns = [ path('', views.index, name='index'), path('article/<int:pk>/', views.detail, name='detail'), path('article/creer/', views.creer_article, name='creer'), path('article/<int:pk>/modifier/', views.modifier_article, name='modifier'), path('article/<int:pk>/supprimer/', views.supprimer_article,name='supprimer'), ]
7
Liens dans les templates & vérification
▾

Ajoute des boutons "Modifier" et "Supprimer" dans le template de détail, visibles uniquement pour l'auteur de l'article.

templates/blog/detail.html — ajouter après le contenu
{% if user == article.auteur %} <div class="article-actions"> <a href="{% url 'blog:modifier' article.pk %}">✏️ Modifier</a> <a href="{% url 'blog:supprimer' article.pk %}">🗑️ Supprimer</a> </div> {% endif %}
Afficher les messages flash dans base.html
{% if messages %} <ul class="messages"> {% for message in messages %} <li class="{{ message.tags }}">{{ message }}</li> {% endfor %} </ul> {% endif %}
